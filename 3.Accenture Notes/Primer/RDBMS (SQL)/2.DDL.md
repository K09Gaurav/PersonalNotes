# Pre quiz

## Question 1

### Question
___________ removes data from the table, but structure remains the same.

- A. Truncate
- B. Drop
- C. Trunc
- D. None of the options

---

### Answer
**Truncate**

---

### Explanation

#### Why Correct Answer is Correct

`TRUNCATE` removes all rows from a table while preserving:

- Table structure
- Column definitions
- Constraints
- Indexes

After truncation:

- The table still exists.
- Only the data is removed.

Important exam point:

- TRUNCATE = Remove all records
- Table structure remains unchanged

---

#### Why Option A is Wrong

This option is actually correct.

---

#### Why Option B is Wrong

`DROP` removes the entire database object.

It deletes:

- Table structure
- Data
- Constraints
- Associated metadata

The table no longer exists after a DROP operation.

---

#### Why Option C is Wrong

`TRUNC` is not a valid SQL command for removing table data.

In some databases, `TRUNC()` may exist as a mathematical function but not as a table deletion command.

---

#### Why Option D is Wrong

A valid option exists: TRUNCATE.

---

### Exam Tip

Remember:

- DELETE → Removes selected rows
- TRUNCATE → Removes all rows
- DROP → Removes the table itself

## Question 2

### Question
A relational database consists of a collection of

- A. Keys
- B. Records
- C. Tables
- D. Fields

---

### Answer
**Tables**

---

### Explanation

#### Why Correct Answer is Correct

The relational model stores data in relations.

A relation is implemented as a table.

Therefore, a relational database is fundamentally a collection of tables that are related to one another.

Examples:

- Customer table
- Product table
- Order table

Together they form a relational database.

---

#### Why Option A is Wrong

Keys help establish relationships between tables but do not constitute the database itself.

---

#### Why Option B is Wrong

Records (rows) exist inside tables.

A database contains tables, not merely records.

---

#### Why Option C is Wrong

This option is actually correct.

---

#### Why Option D is Wrong

Fields (columns) exist inside tables.

A database is not a collection of fields.

---

## Question 3

### Question
In a relational database a referential integrity constraint can be done using

- A. Primary Key
- B. Foreign Key
- C. Secondary Key
- D. Composite Key

---

### Answer
**Foreign Key**

---

### Explanation

#### Why Correct Answer is Correct

Referential integrity ensures that relationships between tables remain valid.

A foreign key:

- References a primary key in another table
- Prevents invalid references
- Maintains consistency across tables

Example concept:

- Order table references Customer table
- Every customer ID in Order must exist in Customer

This is enforced using a foreign key.

---

#### Why Option A is Wrong

A primary key uniquely identifies rows within a table.

It does not enforce relationships between tables.

---

#### Why Option B is Wrong

This option is actually correct.

---

#### Why Option C is Wrong

Secondary key is not used for referential integrity.

It is generally used for searching and indexing purposes.

---

#### Why Option D is Wrong

A composite key consists of multiple columns forming a key.

It may participate in relationships but does not specifically represent referential integrity.

---

### Exam Tip

Remember:

- Primary Key → Uniquely identifies rows
- Foreign Key → Maintains relationships between tables

## Question 5

### Question
Which of the following is not modification of the database

- A. Deletion
- B. Sorting
- C. Insertion
- D. Updating

---

### Answer
**Sorting**

---

### Explanation

#### Why Correct Answer is Correct

Database modification operations change stored data.

Common modification operations:

- INSERT
- UPDATE
- DELETE

Sorting only changes the order in which data is displayed.

Sorting:

- Does not alter stored values
- Does not add records
- Does not remove records
- Does not modify records

Therefore, sorting is not considered a database modification.

---

#### Why Option A is Wrong

Deletion removes records from the database.

This is a modification operation.

---

#### Why Option B is Wrong

This option is actually correct.

Sorting merely affects presentation of data.

---

#### Why Option C is Wrong

Insertion adds new records to the database.

This modifies the database.

---

#### Why Option D is Wrong

Updating changes existing data.

This modifies the database.

---

### Exam Tip

Data Modification Language (DML) operations:

- INSERT
- UPDATE
- DELETE

Sorting is a retrieval/display operation rather than a modification operation.

## Question 2

### Question

A table consists of ______ primary keys.

- A. Any number
- B. 1
- C. 2
- D. 4

---

### Answer

**1**

---

### Explanation

#### Why Correct Answer is Correct

A table can have only one PRIMARY KEY.

The primary key uniquely identifies each row in a table.

Even if the primary key is made up of multiple columns (composite primary key), it is still considered a single primary key constraint.

Important exam point:

- One table → One primary key
- One primary key may contain multiple columns

---

#### Why Option A is Wrong

A table cannot have multiple primary keys.

It may have multiple UNIQUE constraints, but only one PRIMARY KEY constraint.

---

#### Why Option B is Wrong

This option is actually correct.

---

#### Why Option C is Wrong

A table cannot have two primary keys.

---

#### Why Option D is Wrong

A table cannot have four primary keys.

## Question 3

### Question

We need to ensure that the amount withdrawn should be less than the credit card limit amount. To ensure this integrity, what type of constraint will be used?

- A. Table level foreign key constraint
- B. Table level check constraint
- C. Column level check constraint
- D. Column level foreign key constraint

---

### Answer

**Table level check constraint**

---

### Explanation

#### Why Correct Answer is Correct

The condition involves comparing two values:

- Amount withdrawn
- Credit card limit

A CHECK constraint is used to enforce business rules.

Since the validation compares multiple columns, the constraint is generally defined at the table level.

Example logic:

AmountWithdrawn < CreditLimit

This requires access to more than one column.

Therefore, a table-level CHECK constraint is appropriate.

---

#### Why Option A is Wrong

A foreign key maintains relationships between tables.

It does not validate withdrawal limits.

---

#### Why Option B is Wrong

This option is actually correct.

A table-level CHECK constraint is commonly used when multiple columns participate in the validation.

---

#### Why Option C is Wrong

Column-level CHECK constraints are usually used when validating only a single column.

This question involves comparing two columns.

---

#### Why Option D is Wrong

Foreign keys enforce referential integrity, not business-rule validation.

---

### Exam Tip

Use:

- CHECK → Business rules
- FOREIGN KEY → Relationships between tables

## Question 4

### Question

An emp table contains fields employ_name, desig and salary.

How do you drop column salary?

- A. alter table emp drop column salary;
- B. alter table emp delete salary;
- C. delete from emp where column = salary;
- D. alter table emp delete column salary;

---

### Answer

**alter table emp drop column salary;**

---

### Explanation

#### Why Correct Answer is Correct

The ALTER TABLE command modifies table structure.

DROP COLUMN removes a column from an existing table.

The statement:

alter table emp drop column salary;

removes the salary column while keeping the rest of the table intact.

---

#### Why Option A is Wrong

This option is actually correct.

---

#### Why Option B is Wrong

DELETE removes rows, not columns.

The syntax is also invalid.

---

#### Why Option C is Wrong

This deletes records, not table columns.

The syntax is unrelated to dropping a column.

---

#### Why Option D is Wrong

DELETE COLUMN is not valid SQL syntax.

The correct keyword is DROP COLUMN.

---

## Question 5

### Question

Which of the following options is not correct?

- A. alter table emp add column_name varchar(25);
- B. alter table emp drop column column_name;
- C. alter emp drop column_name;
- D. alter table emp modify name varchar(30);

---

### Answer

**alter emp drop column_name;**

---

### Explanation

#### Why Correct Answer is Correct

The ALTER TABLE command requires the TABLE keyword.

Correct syntax begins with:

alter table table_name ...

The statement:

alter emp drop column_name;

is invalid because TABLE is missing.

---

#### Why Option A is Wrong

Valid syntax for adding a column.

---

#### Why Option B is Wrong

Valid syntax for dropping a column.

---

#### Why Option C is Wrong

This option is actually the incorrect statement.

The TABLE keyword is missing.

---

#### Why Option D is Wrong

MODIFY is a valid ALTER TABLE operation in many SQL implementations.

It is used to change a column definition.

---

### Exam Tip

Common ALTER TABLE operations:

- ADD
- DROP COLUMN
- MODIFY

Always remember the structure:

ALTER TABLE table_name ...
