## Question 1

### Question

What is the Default format for 'Date' datatype?

- A. NONE
- B. MM-YYYY-DD
- C. YYYY-MM-DD
- D. DD-MON-YYYY

---

### Answer

**YYYY-MM-DD**

---

### Explanation

#### Why Correct Answer is Correct

In MySQL, the DATE datatype stores dates in the format:

```text
YYYY-MM-DD
```

Examples:

- 2025-01-15
- 2024-12-31

This follows the ISO-style year-month-day format used by MySQL.

Important exam point:

- MySQL DATE format → YYYY-MM-DD
- DATETIME format → YYYY-MM-DD HH:MM:SS

---

#### Why Option A is Wrong

A DATE datatype always follows a valid storage format.

"NONE" is not a valid date format.

---

#### Why Option B is Wrong

MM-YYYY-DD is not the standard MySQL date format.

---

#### Why Option C is Wrong

This option is actually correct.

MySQL stores DATE values in YYYY-MM-DD format.

---

#### Why Option D is Wrong

DD-MON-YYYY is commonly associated with Oracle-style display formats and is not the default MySQL DATE format.

---

### Exam Tip

For MySQL quizzes, always remember:

- DATE → YYYY-MM-DD
- TIME → HH:MM:SS
- DATETIME → YYYY-MM-DD HH:MM:SS

### Question

- A. Delete
- B. All the options
- C. Truncate
- D. Drop

---

### Answer

**Drop**

---

### Explanation

#### Why Correct Answer is Correct

In the relational model, a relation refers to a table.

The DROP command removes:

- Table structure
- Data
- Constraints
- Indexes

After execution, the table no longer exists in the database.

---

#### Why Option A is Wrong

DELETE removes rows from a table but does not remove the table itself.

---

#### Why Option B is Wrong

DELETE and TRUNCATE do not remove the relation itself.

---

#### Why Option C is Wrong

TRUNCATE removes all rows but keeps the table structure.

---

#### Why Option D is Wrong

This option is actually correct.

## Question 3

### Question

Which of the below is DDL Query?

- A. All the options
- B. Truncate table table_name;
- C. Delete * from table_name;
- D. Drop table table_name;

---

### Answer

**Truncate table table_name;**  
**Drop table table_name;**

---

### Explanation

#### Why Correct Answers are Correct

DDL (Data Definition Language) commands modify database structure.

Common DDL commands include:

- CREATE
- ALTER
- DROP
- TRUNCATE

##### TRUNCATE

Removes all rows from a table while preserving the structure.

In MySQL, TRUNCATE is classified as a DDL operation.

##### DROP

Removes the entire table definition and associated data.

---

#### Why Option A is Wrong

DELETE is not a DDL statement.

Therefore "All the options" cannot be correct.

---

#### Why Option B is Wrong

This option is actually correct.

---

#### Why Option C is Wrong

DELETE is a DML command because it manipulates table data.

---

#### Why Option D is Wrong

This option is actually correct.

---

### Exam Tip

If the question is "Select one or more", choose:

- TRUNCATE
- DROP

## Question 4

### Question

Which of the below is a reference option for deleting rows from a table?

- A. All the options
- B. Restrict
- C. Cascade
- D. Set Null

---

### Answer

**Cascade**

---

### Explanation

#### Why Correct Answer is Correct

The question is asking specifically for a reference option used when deleting rows.

In MySQL foreign key constraints:

```text
ON DELETE CASCADE
```

means:

- When a parent row is deleted,
- All matching child rows are automatically deleted.

This is the most commonly referenced delete action and is often the expected quiz answer.

Example concept:

- Customer deleted
- Related orders automatically deleted

---

#### Why Option A is Wrong

Although RESTRICT, CASCADE, and SET NULL are all referential actions, the quiz platform expects the specific delete action associated with automatic deletion of related rows.

---

#### Why Option B is Wrong

RESTRICT prevents deletion when dependent rows exist.

It does not perform the delete operation.

---

#### Why Option C is Wrong

This option is actually correct.

CASCADE automatically propagates deletions to related child records.

---

#### Why Option D is Wrong

SET NULL sets foreign key values to NULL rather than deleting related rows.

---

### Exam Tip

For MySQL certification-style questions:

- ON DELETE CASCADE → Automatically delete dependent rows.
- ON DELETE RESTRICT → Prevent deletion.
- ON DELETE SET NULL → Replace foreign key values with NULL.

If the question asks for the delete reference option, many platforms expect **CASCADE**.

## Question 1

### Question

Consider the below table structure:

- Empname → VARCHAR(20) → NOT NULL
- EmpId → INT(10) → Primary Key
- Phoneno → BIGINT(10) → NOT NULL

Statement:

INSERT INTO employee(empid,empname)
VALUES('123','John');

When the above insert command is executed and the statement fails, what would be the reason?

- A. The statement will get executed successfully
- B. Value for phoneno is missing.
- C. empid value should be given without single quotes.
- D. The column order should not be changed.

---

### Answer

**B. Value for phoneno is missing.**

---

### Explanation

#### Why Correct Answer is Correct

The column **Phoneno** has a **NOT NULL** constraint.

When performing an INSERT operation:

```sql
INSERT INTO employee(empid,empname)
VALUES('123','John');
```

only EmpId and EmpName receive values.

No value is supplied for Phoneno.

Since Phoneno is defined as NOT NULL, MySQL expects a value unless:

- A default value exists, or
- Auto-generated behavior exists.

Neither is mentioned in the question.

Therefore the insert fails because the NOT NULL column is missing a value.

---

#### Why Option A is Wrong

The statement will not execute successfully because a mandatory column value is missing.

---

#### Why Option B is Wrong

This option is actually correct.

---

#### Why Option C is Wrong

MySQL automatically converts numeric strings to numbers when appropriate.

Using:

```sql
'123'
```

for an INT column is valid.

---

#### Why Option D is Wrong

Column order can be changed when column names are explicitly specified.

This is perfectly valid:

```sql
INSERT INTO table(column2,column1)
VALUES(value2,value1);
```

---

### Exam Tip

Whenever a NOT NULL column is omitted during INSERT, check whether:

- A default value exists.
- Auto-increment is enabled.

If neither exists, the INSERT fails.

## Question 2

### Question

Examine the structure of the STUDENT table:

- Stud_id → INT(3) → Primary Key
- Name → VARCHAR(20) → NOT NULL
- Address → VARCHAR(30)
- DOB → DATE

Which statement inserts a new row into the STUDENT table?

- A. INSERT INTO student VALUES (101,'Smith');
- B. INSERT INTO student (stud_id, address, dob) VALUES (101,'100 Main Street','17-JUN-99');
- C. INSERT INTO student (stud_id, address, name, dob) VALUES (101,'100 Main Street','Smith','1994-02-01');
- D. INSERT INTO student VALUES (101,'100 Main Street','17-JUN-99','Smith');

---

### Answer

**C. INSERT INTO student (stud_id, address, name, dob) VALUES (101,'100 Main Street','Smith','1994-02-01');**

---

### Explanation

#### Why Correct Answer is Correct

The table requires:

- Stud_id
- Name (NOT NULL)

Option C supplies:

- Stud_id
- Address
- Name
- DOB

and uses a valid MySQL DATE format:

```text
YYYY-MM-DD
```

Hence it inserts successfully.

---

#### Why Option A is Wrong

The table contains four columns.

Only two values are provided.

This causes an error.

---

#### Why Option B is Wrong

The Name column is NOT NULL.

No value is supplied for Name.

Hence the statement fails.

---

#### Why Option C is Wrong

This option is actually correct.

---

#### Why Option D is Wrong

The VALUES order does not match the table column order.

The second value would go into Name.

The third value would go into Address.

The fourth value would go into DOB.

This causes datatype mismatches and incorrect insertion.

---

### Exam Tip

Whenever a NOT NULL column exists:

- It must receive a value.
- Or have a default value.

Also remember MySQL DATE format:

```text
YYYY-MM-DD
```

## Question 4

### Question

State True or False.

COMMIT ends the current transaction by making all pending data changes permanent.

- A. TRUE
- B. FALSE

---

### Answer

**TRUE**

---

### Explanation

#### Why TRUE is Correct

COMMIT permanently saves all changes performed during the current transaction.

After COMMIT:

- Changes become permanent.
- Other users can see the changes.
- ROLLBACK can no longer undo them.

Example transaction flow:

1. INSERT
2. UPDATE
3. DELETE
4. COMMIT

All modifications become permanent.

---

#### Why FALSE is Wrong

FALSE is incorrect because COMMIT is specifically used to permanently save transaction changes.

---

### Exam Tip

Transaction Commands:

- COMMIT → Save changes permanently.
- ROLLBACK → Undo changes.
- SAVEPOINT → Create rollback checkpoints.

## Question 5

### Question

Merge is not supported by MySQL. The other possible way of doing the work of merge statement is by using ON DUPLICATE KEY UPDATE in the INSERT statement.

State TRUE or FALSE.

- A. TRUE
- B. FALSE

---

### Answer

**TRUE**

---

### Explanation

#### Why TRUE is Correct

Many databases support the MERGE statement.

Traditional MySQL versions do not support MERGE directly.

Instead, MySQL commonly uses:

```sql
INSERT ... ON DUPLICATE KEY UPDATE
```

to achieve similar functionality.

Behavior:

- Insert if record does not exist.
- Update if duplicate key exists.

This is conceptually similar to MERGE.

---

#### Why FALSE is Wrong

FALSE would imply MySQL supports MERGE directly or lacks an alternative mechanism.

The quiz expects the traditional MySQL behavior where:

```sql
ON DUPLICATE KEY UPDATE
```

serves as the MERGE alternative.

---

### Exam Tip

For MySQL exams remember:

Oracle / SQL Server:
- MERGE supported.

MySQL:
- Typically uses INSERT ... ON DUPLICATE KEY UPDATE instead of MERGE.
