# Introduction

Security is one of the most important aspects of cloud computing. Unlike traditional on-premises infrastructure—where an organization is responsible for securing everything—cloud security is based on a **Shared Responsibility Model**.

In AWS, **security responsibilities are divided between AWS and the customer**.

AWS manages the security of the underlying cloud infrastructure, while customers are responsible for securing everything they deploy and configure within the cloud.

> [!IMPORTANT]
> **AWS is responsible for Security *OF* the Cloud.**
>
> **Customers are responsible for Security *IN* the Cloud.**

This is one of the most frequently asked AWS interview topics.

---

# What is the AWS Shared Responsibility Model?

## Definition

The **AWS Shared Responsibility Model** defines which security tasks are handled by AWS and which are handled by the customer.

The model ensures:

- AWS secures the cloud infrastructure.
- Customers secure their applications, data, and configurations.

The exact customer responsibilities may vary depending on the AWS service being used (IaaS, PaaS, or Serverless), but the basic principle always remains the same.

# AWS Responsibilities (Security OF the Cloud)

AWS is responsible for protecting the **global cloud infrastructure**.

Customers do **not** have direct access to these components.

AWS continuously monitors, maintains, and secures them.

# AWS Responsibilities

## 1. Securing Edge Locations

AWS operates hundreds of **Edge Locations** worldwide.

AWS is responsible for:

- Physical protection
- Environmental controls
- Network security
- Operational maintenance

Customers simply use these services.

---

## 2. Monitoring Physical Device Security

AWS protects the physical infrastructure hosting customer workloads.

This includes:

- Servers
- Storage devices
- Networking hardware
- Data center equipment

AWS monitors these devices 24×7.

---

## 3. Physical Access Control

AWS ensures that only authorized personnel can enter AWS data centers.

Security measures include:

- Security guards
- CCTV surveillance
- Biometric authentication
- Multi-factor physical access controls

Customers never manage these facilities.

---

## 4. Database Patching *(Managed Database Services)*

For managed database services (such as Amazon RDS), AWS is responsible for:

- Installing security patches
- Updating database software
- Infrastructure maintenance

> [!NOTE]
> If you manage your own database on an **EC2 instance**, you—not AWS—are responsible for patching it.

---

## 5. Secure Disposal of Physical Storage Devices

When AWS retires storage hardware, it ensures that customer data cannot be recovered.

AWS securely:

- Destroys storage devices
- Erases disks
- Follows industry-standard disposal procedures

This prevents unauthorized access to previously stored data.

---

# Additional AWS Responsibilities

AWS also secures:

- Data centers
- Physical servers
- Networking equipment
- Hypervisors
- Global infrastructure
- Availability Zones
- Regions

# Customer Responsibilities (Security IN the Cloud)

Customers are responsible for securing everything they create, configure, or upload into AWS.

---

# Customer Responsibilities

## 1. Identity and Access Management (IAM)

Customers control:

- IAM Users
- IAM Groups
- IAM Roles
- IAM Policies

This determines:

- Who can access AWS resources.
- What actions they are allowed to perform.

> [!IMPORTANT]
> AWS provides IAM.
>
> Customers configure IAM.

---

## 2. Data Encryption

Customers decide:

- Which data should be encrypted.
- Which encryption services to use.
- How encryption keys are managed (unless fully managed services are used).

AWS provides tools such as:

- AWS KMS
- Server-Side Encryption

Customers choose whether and how to use them.

---

## 3. Account Security

Customers are responsible for protecting their AWS accounts.

This includes:

- Strong passwords
- Multi-Factor Authentication (MFA)
- Monitoring suspicious activity
- Rotating credentials

AWS cannot prevent compromised credentials if customers fail to secure them.

---

## 4. Restricting Access

Customers should follow the **Principle of Least Privilege**.

Users should receive only the permissions required to perform their jobs.

For example:

- Developers should not access billing.
- HR should not manage EC2.
- Finance should not administer networking.

---

## 5. Customer Data

Customers own and secure their data.

Responsibilities include:

- Data classification
- Data backups
- Data encryption
- Data access policies
- Compliance requirements

---

## 6. Application Security

Customers secure:

- Web applications
- APIs
- Source code
- Authentication
- Authorization

AWS provides the infrastructure, but application security remains the customer's responsibility.

---

## 7. Firewall Configuration

Customers configure network security services such as:

- Security Groups
- Network ACLs
- VPC Firewall Rules

Improper configuration can expose cloud resources to the Internet.

---

# Shared Responsibility by Service Type

Customer responsibilities change depending on the AWS service model.

| Service Type | AWS Manages | Customer Manages |
|--------------|-------------|------------------|
| EC2 (IaaS) | Hardware, Networking, Hypervisor | OS, Applications, Data, IAM |
| RDS (Managed Database) | Infrastructure + Database Software | Database Data, Users, Permissions |
| Lambda (Serverless) | Infrastructure, Runtime | Application Code, IAM, Data |

> [!TIP]
> The more **managed** the AWS service, the fewer responsibilities the customer has.

# Common Examples

## Example 1

An EC2 server is hacked because the SSH port is open to the Internet.

Who is responsible?

**Customer**

Reason:

The customer configured the Security Group incorrectly.

---

## Example 2

A physical hard drive inside an AWS data center fails.

Who is responsible?

**AWS**

Reason:

AWS manages physical hardware.

---

## Example 3

Sensitive customer data is stored without encryption.

Who is responsible?

**Customer**

Reason:

AWS provides encryption services, but customers choose whether to enable them.

---

## Example 4

Someone steals a physical server from an AWS data center.

Who is responsible?

**AWS**

Reason:

Physical infrastructure security belongs to AWS.

# Interview One-Liners

**AWS Shared Responsibility Model**
> A security model in which AWS is responsible for securing the cloud infrastructure, while customers are responsible for securing their data, applications, identities, and configurations within the cloud.

**Security OF the Cloud**
> AWS is responsible for protecting the physical infrastructure, networking, hardware, and managed services that make up the AWS Cloud.

**Security IN the Cloud**
> Customers are responsible for securing their workloads, including IAM, applications, data, encryption, firewall rules, and account security.

**IAM**
> AWS Identity and Access Management (IAM) controls who can access AWS resources and what actions they are permitted to perform.

**Principle of Least Privilege**
> A security principle that grants users only the minimum permissions required to perform their job responsibilities.
