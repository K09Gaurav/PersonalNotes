# Introduction

**Amazon Elastic Compute Cloud (Amazon EC2)** is one of the most fundamental and widely used services in AWS. It provides **resizable virtual servers**, known as **EC2 Instances**, that allow users to run applications in the cloud without purchasing or maintaining physical hardware.

Instead of buying expensive servers, organizations can **rent computing resources on demand**, paying only for what they use.

EC2 forms the backbone of many cloud applications and is considered an **Infrastructure as a Service (IaaS)** offering.

> [!IMPORTANT]
> **Amazon EC2 = Rent virtual servers in the cloud.**

---

# What is Amazon EC2?

## Definition

**Amazon Elastic Compute Cloud (EC2)** is a cloud service that provides **resizable virtual machines (instances)** that can run applications, websites, databases, APIs, and other workloads.

Users have full control over the operating system, installed software, networking, and storage attached to the instance.

EC2 allows developers to:

- Launch virtual servers within minutes.
- Choose CPU, memory, storage, and networking configurations.
- Scale resources up or down based on demand.
- Pay only for the resources they use.

---

## Why is it called "Elastic"?

The word **Elastic** refers to the ability to **increase or decrease computing resources** as application demand changes.

For example:

- During high traffic → Launch additional EC2 instances.
- During low traffic → Terminate unused instances.

This elasticity helps optimize performance while reducing costs.

---

# EC2 Terminology

## Instance

An **EC2 Instance** is a virtual machine running in AWS.

Think of it as renting a computer in the cloud.

Each instance has:

- CPU
- RAM
- Storage
- Network Interface
- Operating System

> [!TIP]
> Developers often say **"Launch an EC2 Instance"**, which simply means creating a new virtual server.

---

## Is EC2 Serverless?

**No.**

Unlike AWS Lambda, EC2 requires you to manage the server.

With EC2, you are responsible for:

- Installing the operating system.
- Configuring software.
- Applying updates.
- Managing applications.
- Monitoring the server.

Therefore, EC2 is **not** a serverless service.

---

# Benefits of Amazon EC2

EC2 offers several advantages over traditional physical servers.

## 1. No Upfront Hardware Investment

No need to purchase physical servers.

AWS provides the infrastructure.

## 2. Elastic Scaling

Increase or decrease computing capacity based on workload demand.

## 3. Full Control

Users can:

- Choose the operating system.
- Install custom software.
- Configure networking.
- Manage storage.
## 4. Fast Provisioning

Servers can be launched within minutes instead of waiting days or weeks for physical hardware.

## 5. Pay-as-you-go Pricing

Only pay for the resources used.

# EC2 Pricing Options

AWS offers several pricing models to suit different workloads.

---

## 1. On-Demand Instances

### Definition

Pay only for the time the instance runs.

No long-term commitment.

---

#### Characteristics

- No upfront payment
- Flexible
- Ideal for short-term workloads
- Pay by usage

---

#### Best Use Cases

- Development
- Testing
- Temporary workloads
- Unpredictable traffic

> [!TIP]
> **On-Demand = Rent only when needed.**

---

## 2. Dedicated Hosts

### Definition

A **Dedicated Host** provides an entire physical server dedicated to one customer.

No other AWS customers share the hardware.

---

#### Advantages

- Meets licensing requirements.
- Supports compliance regulations.
- No multi-tenancy.

---

#### Best Use Cases

- Enterprise software licensing
- Regulatory compliance
- Dedicated hardware requirements

---

## 3. Spot Instances

### Definition

Spot Instances allow customers to use AWS's unused computing capacity at significantly reduced prices.

Pricing changes according to supply and demand.

---

#### How Spot Instances Work

- Customer specifies a maximum price.
- AWS launches the instance if capacity is available.
- If AWS needs the capacity back or the Spot price exceeds the maximum bid, the instance is interrupted.

---

#### Advantages

- Up to **90% cheaper** than On-Demand pricing.

---

#### Limitations

- Can be terminated unexpectedly.
- Not suitable for critical applications.

---

#### Best Use Cases

- Batch processing
- Data analysis
- Machine Learning training
- Rendering jobs
- Fault-tolerant applications

---

## 4. Reserved Instances (RI)

### Definition

Reserved Instances provide significant discounts in exchange for a **1-year or 3-year commitment**.

---

#### Advantages

- Lower cost
- Predictable pricing
- Suitable for stable workloads

---

#### Best Use Cases

- Production servers
- Databases
- Long-running enterprise applications

---

## EC2 Pricing Comparison

| Pricing Model | Commitment | Cost | Best For |
|---------------|------------|------|----------|
| On-Demand | None | Highest | Short-term workloads |
| Spot | None | Lowest | Interruptible workloads |
| Reserved Instance | 1 or 3 Years | Lower | Long-term predictable workloads |
| Dedicated Host | Dedicated Hardware | Highest | Licensing & Compliance |

A **Launch Template** contains predefined configuration settings used to launch EC2 instances automatically.

It can include:

- AMI

- Security Groups

## 3. Amazon Machine Images (AMI)

### Definition

An **Amazon Machine Image (AMI)** is a preconfigured template used to launch EC2 instances.

An AMI includes:

- Operating System
- Software
- Configuration
- Applications

AWS provides:

- Official AMIs
- Community AMIs
- Marketplace AMIs
- Custom AMIs

> [!TIP]
> **AMI = Blueprint for an EC2 Instance**

---

### EC2 Image Builder

AWS Image Builder helps automate the creation and maintenance of custom AMIs.

Benefits:

- Consistent server configurations.
- Automated image updates.
- Improved security.

---

## 4. Elastic Block Store (EBS)

### Definition

Amazon **Elastic Block Store (EBS)** provides persistent block storage for EC2 instances.

Think of it as an external hard drive attached to a virtual server.

---

### EBS Volumes

An **EBS Volume** is a storage disk attached to an EC2 instance.

Features:

- Persistent storage
- Can be detached and attached to another instance
- Multiple storage types available

Examples:

- SSD
- HDD
- Magnetic Drives

---

### EBS Snapshots

A **Snapshot** is a backup of an EBS volume at a specific point in time.

Uses:

- Disaster Recovery
- Backup
- Migration
- Cloning

---

### Lifecycle Manager

Automates:

- Snapshot creation
- Snapshot deletion
- Backup scheduling

---

## 5. Network & Security

---

### Security Groups

#### Definition

A **Security Group** acts as a **virtual firewall** for EC2 instances.

It controls:

- Inbound traffic
- Outbound traffic

Multiple EC2 instances can share the same Security Group.

Changes take effect immediately.

> [!TIP]
> **Security Group = EC2 Firewall**

---

### Elastic IP Address

#### Definition

An **Elastic IP** is a permanent public IPv4 address.

Normally:

Stopping and restarting an EC2 instance may change its public IP.

Elastic IP solves this problem by providing a fixed public IP.

---

### Placement Groups

Placement Groups control how EC2 instances are physically placed within AWS infrastructure.

Strategies include:

- Cluster
- Partition
- Spread

Used to optimize:

- Performance
- Availability
- Fault tolerance

---

### Key Pairs

#### Definition

A **Key Pair** is used for secure authentication when connecting to Linux EC2 instances.

It consists of:

- Public Key (stored by AWS)
- Private Key (.pem file) (stored by user)

Without the private key, login is generally not possible.

---

### Network Interfaces

A **Network Interface (ENI)** acts as a virtual network card.

It contains:

- Private IP
- Public IP
- MAC Address
- Security Groups

An EC2 instance can have multiple network interfaces.

---

## 6. Load Balancing

### Load Balancer

A **Load Balancer** distributes incoming requests across multiple EC2 instances.

Benefits:

- High Availability
- Fault Tolerance
- Better Performance

AWS supports:

- Application Load Balancer (ALB)
- Network Load Balancer (NLB)
- Classic Load Balancer (Legacy)

---

## 7. EC2 Auto Scaling

### Definition

EC2 Auto Scaling automatically increases or decreases the number of EC2 instances based on demand.

It uses:

- Scaling Policies
- Health Checks
- Launch Templates

Benefits:

- High Availability
- Cost Optimization
- Elastic Infrastructure

Example:

```text
Normal Traffic → 2 Instances

High Traffic → 10 Instances

Low Traffic → 2 Instances
```

# Interview One-Liners

**Amazon EC2**
> A cloud computing service that provides scalable virtual servers (instances) on demand.

> A virtual machine running in AWS that provides configurable compute capacity.

> A preconfigured template containing the operating system and software used to launch EC2 instances.

> Persistent block storage that can be attached to EC2 instances.

> A stateful virtual firewall that controls inbound and outbound traffic for EC2 instances.

> A static public IPv4 address that can be remapped between EC2 instances.

**EC2 Auto Scaling**
> A service that automatically launches or terminates EC2 instances based on workload demand and health checks.

**Spot Instance**
> An EC2 purchasing option that uses spare AWS capacity at discounted prices, with the possibility of interruption.

**Reserved Instance**
> A pricing option that provides significant discounts in exchange for a 1-year or 3-year commitment.

**Dedicated Host**
> A physical server dedicated to a single AWS customer to meet licensing or compliance requirements.
