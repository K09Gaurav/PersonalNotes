# Cloud Computing

## Definition

**Cloud Computing** is the delivery of computing resources and IT services over the **Internet** instead of maintaining physical hardware on-premises.

Instead of purchasing and managing your own servers, storage devices, networking equipment, and software, you can rent these resources from cloud providers whenever required.

A cloud can be thought of as a **virtual data center** that is accessible through the Internet. Users can provision, manage, and scale resources with minimal effort.

---

## Services Available in Cloud Computing

Cloud providers offer a wide variety of services, including:

- **Storage Services**
  - Databases
  - File storage
  - Object storage
  - Backup and disaster recovery

- **Compute Services**
  - Virtual Machines (VMs)
  - Containers
  - Serverless computing

- **Networking**
  - Virtual networks
  - Load balancers
  - DNS services
  - VPN connections

- **Data & Analytics**
  - Big Data processing
  - Data Warehousing
  - Business Intelligence
  - Data Analytics

- **Artificial Intelligence & Machine Learning**
  - AI APIs
  - Machine Learning platforms
  - Speech recognition
  - Image recognition
  - Natural Language Processing (NLP)

- **Augmented Reality (AR) & Virtual Reality (VR)**
  - Cloud-hosted AR/VR services
  - 3D rendering

- **Security Services**
  - Identity and Access Management (IAM)
  - Encryption
  - Firewalls
  - Security monitoring
  - Threat detection

# Characteristics of Cloud Computing

Cloud computing offers several important characteristics that make it highly flexible and cost-effective.

## 1. On-Demand Self-Service

Resources are available **whenever they are needed**, without requiring manual intervention from the cloud provider.

Users can create:

- Virtual Machines
- Storage
- Databases
- Networking resources

within minutes through a web portal or API.

### Example

Instead of purchasing a hard drive to store photos, you can simply create an account on:

- Google Drive
- Microsoft OneDrive

and immediately start uploading files.

**Key Point**

> [!NOTE]
> No need to purchase hardware or wait for IT approval before using resources.

---

## 2. Pay-As-You-Go (Pay Per Use)

Users are charged **only for the resources they actually consume.**

There is:

- No upfront investment
- No need to purchase expensive hardware
- No maintenance costs for physical infrastructure

Billing is typically based on:

- Compute hours
- Storage used
- Network bandwidth
- Number of requests
- Execution time (for serverless)

### Example

Suppose you need a server for only **10 hours**.

Instead of purchasing a physical server costing thousands of dollars, you can rent a virtual machine from providers like:

- Amazon Web Services (AWS)
- Microsoft Azure
- Google Cloud Platform (GCP)

and pay only for the hours used.

**Key Point**

> [!TIP]
> Cloud computing converts **Capital Expenditure (CapEx)** into **Operational Expenditure (OpEx).**

---

## 3. Auto Scaling

Cloud resources can automatically **increase or decrease** depending on application demand.

When demand increases:

- More servers are added.

When demand decreases:

- Extra servers are removed.

### Benefits

- Handles traffic spikes automatically
- Saves money during low traffic
- Improves application performance
- Reduces manual intervention

### Example

An online shopping website during a festival sale may automatically increase from:

- 5 servers → 50 servers

After the sale:

- 50 servers → 5 servers

---

## 4. Serverless Computing

In a serverless environment, developers only focus on:

- Writing code
- Deploying code

The cloud provider manages:

- Servers
- Operating System
- Scaling
- Patching
- Infrastructure maintenance

Developers never have to manage the underlying hardware.

### Benefits

- Faster development
- Automatic scaling
- Lower operational overhead
- Pay only when the code executes

### Examples

- AWS Lambda
- Azure Functions
- Google Cloud Functions

> [!IMPORTANT]
> **Serverless does NOT mean there are no servers.**
>
> It means **developers do not manage the servers.**

# Types of Cloud Computing Services

Cloud providers generally offer three service models:

1. Infrastructure as a Service (IaaS)
2. Platform as a Service (PaaS)
3. Software as a Service (SaaS)

# Infrastructure as a Service (IaaS)

## Definition

Infrastructure as a Service provides the **basic computing infrastructure** required to build applications.

The cloud provider supplies:

- Virtual Machines
- Storage
- Networking
- Compute resources

The customer is responsible for:

- Installing Operating System
- Managing applications
- Installing software
- Configuring security
- Managing data

### Examples

- Amazon EC2
- Microsoft Azure Virtual Machines
- Google Compute Engine
- Rackspace

### Responsibilities

| Cloud Provider | Customer |
|---------------|----------|
| Hardware | Operating System |
| Networking | Applications |
| Storage | Runtime |
| Virtualization | Data |

---

# Platform as a Service (PaaS)

## Definition

Platform as a Service provides a complete development platform where developers can build, test, and deploy applications without worrying about infrastructure.

The cloud provider manages:

- Infrastructure
- Operating System
- Runtime
- Middleware

Developers only focus on:

- Writing code
- Deploying applications

### Examples

- Google App Engine
- Azure App Service
- Heroku
- GoDaddy (as per course example)

### Benefits

- Faster development
- No server management
- Easy deployment
- Built-in development tools

---

# Software as a Service (SaaS)

## Definition

Software as a Service delivers complete software applications over the Internet.

Users simply:

- Open a browser
- Log in
- Start using the software

No installation or maintenance is required.

The provider manages everything.

### Examples

- Gmail
- Microsoft 365
- Google Docs
- Dropbox
- Salesforce

### Benefits

- No installation
- Accessible anywhere
- Automatic updates
- Subscription-based pricing

---

# Comparison of IaaS, PaaS, and SaaS

| Feature | IaaS | PaaS | SaaS |
|----------|------|------|------|
| Infrastructure Managed By | Provider | Provider | Provider |
| Operating System | Customer | Provider | Provider |
| Runtime | Customer | Provider | Provider |
| Applications | Customer | Customer | Provider |
| User Focus | Infrastructure | Application Development | Using Software |
| Example | Rackspace, AWS EC2 | GoDaddy, Azure App Service | Gmail |

# Cloud Deployment Models

## Overview

A **Cloud Deployment Model** defines **where cloud resources are hosted**, **who owns the infrastructure**, and **who can access it**.

The four primary deployment models are:

1. Private Cloud
2. Public Cloud
3. Hybrid Cloud
4. Multi-Cloud

---

# 1. Private Cloud

## Definition

A **Private Cloud** is a cloud environment dedicated to a **single organization**.

Unlike a traditional on-premises data center, a private cloud provides cloud-like capabilities such as:

- On-demand provisioning
- Elastic scalability
- Self-service resource allocation
- Consumption-based charging

The infrastructure is typically managed by the organization's IT department or a dedicated cloud provider.

> [!IMPORTANT]
> A **Private Cloud is NOT simply a virtualized data center.**

### Difference Between a Virtualized Data Center and a Private Cloud

| Virtualized Data Center | Private Cloud |
|--------------------------|---------------|
| Uses virtualization technology | Uses virtualization plus cloud capabilities |
| Resources often manually allocated | Resources can be provisioned on demand |
| Usually fixed capacity | Elastic and scalable |
| Usually not consumption-based | Pay based on usage (internally or externally) |
| Traditional infrastructure | Cloud-like environment |

### Characteristics

- Dedicated to one organization
- High security
- High privacy
- Greater control
- Custom infrastructure
- Better compliance with regulations

### Advantages

- Maximum security
- Full administrative control
- Better regulatory compliance
- Custom networking and security policies

### Disadvantages

- Higher cost
- Infrastructure maintenance responsibility
- Requires skilled IT staff
- Limited scalability compared to public cloud

### Best For

- Banks
- Government agencies
- Healthcare organizations
- Defense organizations
- Financial institutions

---

# 2. Public Cloud

## Definition

A **Public Cloud** is owned and managed by a **third-party Cloud Service Provider (CSP)**.

Resources are shared among multiple customers using a **multi-tenant architecture**.

Anyone can purchase and use these cloud services.

### Major Public Cloud Providers

- Amazon Web Services (AWS)
- Microsoft Azure
- Google Cloud Platform (GCP)
- IBM Cloud
- Oracle Cloud

### Characteristics

- Third-party managed
- Shared infrastructure
- Multi-tenant
- Highly scalable
- Internet accessible
- Pay-as-you-go pricing

### Advantages

- Low upfront cost
- No infrastructure management
- Automatic scaling
- High availability
- Global infrastructure

### Disadvantages

- Less control over hardware
- Shared environment
- Compliance limitations for some industries

### Best For

- Startups
- Web applications
- Mobile applications
- Development and testing
- Small and medium businesses

---

# 3. Hybrid Cloud

## Definition

A **Hybrid Cloud** combines:

- Private Cloud
- Public Cloud
- On-Premises Infrastructure

into a single environment where applications and data can move between them.

Organizations use Hybrid Cloud to gain the advantages of both private and public cloud deployments.

### Characteristics

- Mix of multiple deployment models
- Flexible workload placement
- Better compliance
- Better performance optimization

### Example

A bank may:

- Store customer data in a Private Cloud
- Host its website in AWS
- Maintain legacy systems on-premises

All three work together as one solution.

### Advantages

- Flexibility
- Cost optimization
- Regulatory compliance
- Better disaster recovery
- Improved performance

### Best For

Organizations that:

- Already own data centers
- Need strict compliance
- Want gradual cloud migration

> [!TIP]
> Hybrid Cloud = **Combination of Private + Public + On-Premises Infrastructure**

---

# 4. Multi-Cloud

## Definition

A **Multi-Cloud** strategy uses **two or more public cloud providers** simultaneously.

Instead of depending on a single cloud vendor, organizations distribute workloads across multiple providers.

### Example

- AWS for compute
- Azure for Active Directory
- Google Cloud for AI and Machine Learning

### Why Use Multi-Cloud?

- Avoid vendor lock-in
- Use the best services from each provider
- Improve availability
- Geographic optimization
- Cost optimization

### Difference Between Hybrid and Multi-Cloud

| Hybrid Cloud | Multi-Cloud |
|--------------|-------------|
| Combines Private + Public + On-Premises | Uses multiple Public Clouds |
| Focus on integration | Focus on provider diversity |
| Example: AWS + Private Cloud | Example: AWS + Azure + GCP |

---

|----------|---------|---------|---------|-------------|
| Infrastructure Ownership | Single Organization | Third Party | Combination | Multiple Providers |
| Security | Very High | High | High | Depends on Providers |
| Cost | High | Low | Moderate | Moderate |
| Scalability | Moderate | Very High | High | Very High |
| Maintenance | Customer | Provider | Shared | Shared |
| Best For | Sensitive Workloads | General Applications | Enterprise Migration | Large Enterprises |

# Benefits of Cloud Computing

Cloud adoption has grown rapidly because it provides significant business value.

The four major business benefits are:

1. Cost Savings
2. Productivity
3. Operational Resilience
4. Business Agility

---

# 1. Cost Savings

Cloud computing reduces the need for:

- Purchasing hardware
- Building data centers
- Maintaining infrastructure
- Cooling and electricity costs

Organizations pay only for the resources they consume.

### Example

Companies such as:

- Netflix
- Capital One

have retired many of their physical data centers and reported substantial infrastructure savings.

### Benefits

- Lower Capital Expenditure (CapEx)
- Lower maintenance costs
- Better resource utilization

---

# 2. Productivity

Cloud services automate many infrastructure tasks, allowing developers and IT teams to focus on delivering business value.

Automation reduces:

- Manual server provisioning
- Software installation
- Infrastructure management

### Benefits

- Faster deployments
- Less operational work
- Improved developer efficiency
- Better collaboration

---

# 3. Operational Resilience

Cloud platforms provide highly resilient infrastructure designed to minimize downtime.

Cloud providers offer:

- Backup services
- Disaster recovery
- High Availability
- Fault tolerance
- Geographic redundancy

These features reduce outages caused by:

- Power failures
- Hardware failures
- Natural disasters
- Human error
- Security incidents

---

# 4. Business Agility

Cloud computing enables organizations to innovate and respond quickly to changing business needs.

Instead of waiting weeks to purchase and configure hardware, cloud resources can be created within minutes.

### Benefits

- Faster product launches
- Rapid scaling
- Easier expansion into new markets
- Faster experimentation

# 1. Geographic Availability

Cloud providers operate data centers worldwide.

These data centers are organized into:

- Regions
- Availability Zones (AZs)

## Region

A **Region** is a separate geographic location containing one or more data centers.

Examples:

- Mumbai
- Singapore
- Frankfurt
- Virginia

---

## Availability Zone (AZ)

An **Availability Zone** is an isolated data center within a region.

Each region contains multiple Availability Zones to improve:

- Reliability
- High Availability
- Disaster Recovery

If one Availability Zone fails, workloads can continue running in another.

# 4. Pricing Model

All major cloud providers follow similar pricing strategies.

## On-Demand Pricing

Pay only for resources used.

No long-term commitment.

---

## Committed Usage Discounts

Reduced pricing for long-term commitments.

### Examples

AWS:

- Reserved Instances

GCP:

- Sustained Use Discounts

---

## Serverless Pricing

Charges are based only on execution time.

Examples:

| Provider | Serverless Service |
|----------|--------------------|
| AWS | Lambda |
| Azure | Azure Functions |
| GCP | Cloud Functions |

Billing is typically calculated in **100-millisecond increments**, meaning users pay only for the compute time consumed.
