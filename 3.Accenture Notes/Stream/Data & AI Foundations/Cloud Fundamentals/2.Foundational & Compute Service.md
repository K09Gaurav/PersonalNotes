# Introduction

Cloud computing introduces several foundational concepts that form the basis of modern cloud infrastructure. Understanding these terms is essential because they are used across all major cloud providers such as **Amazon Web Services (AWS)**, **Microsoft Azure**, and **Google Cloud Platform (GCP)**.

These concepts describe how data is stored, how applications run, and how cloud resources are managed.

# Foundational Cloud Computing Terms

## 1. Data

### Definition

**Data** is any digital information stored and processed by a computer.

Examples include:

- Text documents
- Images
- Videos
- Audio files
- Emails
- Application data
- Customer information
- Logs
- Sensor readings

Computers store all data in the form of **bits** and **bytes** on physical storage devices such as:

- Hard Disk Drives (HDD)
- Solid State Drives (SSD)
- Optical media

In cloud computing, users do not interact directly with physical storage devices. Instead, cloud providers offer managed storage services that abstract away the underlying hardware.

### Example

When you upload a photo to **Google Drive**, you are storing data on cloud-managed storage rather than on your personal computer.

> [!NOTE]
> Cloud users interact with storage services, not the physical disks that hold the data.

---

# 2. File Store (File System)

## Definition

A **File Store** (or **File System**) is a storage system designed to organize and manage files.

It allows users to:

- Store files
- Retrieve files
- Modify files
- Delete files
- Organize files into folders/directories

File storage is ideal for unstructured data such as:

- Documents
- Images
- Videos
- Music
- PDFs
- Backups

### Characteristics

- Hierarchical folder structure
- Low storage cost
- Optimized for large files
- Easy sharing
- Simple file management

### Examples

- Google Drive
- Microsoft OneDrive
- Dropbox
- Amazon EFS (Elastic File System)
- Azure Files

### Common Use Cases

- Personal storage
- Shared team documents
- Media storage
- Backup archives

---

# 3. Database

## Definition

A **Database** is a structured system used to store, organize, and retrieve data efficiently.

Unlike file storage, databases organize information using specialized data structures and indexing techniques to enable fast searching and retrieval.

Databases are particularly useful for applications with complex relationships between data.

### Characteristics

- Structured storage
- Fast data retrieval
- Indexing for performance
- Supports relationships between data
- Handles concurrent users

### Example Data

| Customer ID | Name | City |
|-------------|------|------|
| 101 | Rahul | Delhi |
| 102 | Priya | Mumbai |
| 103 | Aman | Bengaluru |

Applications such as:

- Banking systems
- E-commerce websites
- Social media platforms
- Hospital management systems

typically rely on databases.

### Examples of Database Services

- Amazon RDS
- Amazon DynamoDB
- Azure SQL Database
- Google Cloud SQL
- PostgreSQL
- MySQL
- Oracle Database

---

# File Storage vs Database

| Feature | File Storage | Database |
|----------|--------------|-----------|
| Stores | Files | Structured Data |
| Organization | Folders and files | Tables, documents, key-value pairs, etc. |
| Search Speed | Slower for complex queries | Optimized using indexes |
| Best For | Images, videos, documents | Applications and business data |
| Relationships | Minimal | Supports complex relationships |

# 4. Compute

## Definition

**Compute** refers to the processing power used to execute instructions and perform calculations.

Every application requires compute resources to:

- Execute code
- Process requests
- Perform calculations
- Run operating systems
- Handle user interactions

Compute is primarily provided by the **Central Processing Unit (CPU)**, although modern cloud environments may also use:

- GPUs (Graphics Processing Units)
- TPUs (Tensor Processing Units)

for specialized workloads like AI and Machine Learning.

### Examples

Whenever you:

- Open a web page
- Run a mobile app
- Stream a video
- Train an AI model

compute resources are being used.

---

# 5. Server

## Definition

A **Server** is a specialized computer that provides services, resources, or data to other computers (called **clients**) over a network.

Servers are designed to run continuously and support multiple users simultaneously.

### Types of Servers

- Web Server
- Database Server
- Application Server
- File Server
- Mail Server

### Cloud Servers

In cloud computing, servers are typically virtualized and can be created, modified, or deleted within minutes.

### Examples

- Amazon EC2 Instance
- Azure Virtual Machine
- Google Compute Engine

---

# 6. Instance

## Definition

An **Instance** is a running compute resource provided by the cloud.

An instance may represent:

- A physical server
- A virtual machine (VM)
- A container
- A serverless execution environment

Most cloud providers use virtualization, allowing multiple virtual instances to run on a single physical machine.

### Example

Creating an AWS EC2 virtual machine launches a new **instance**.

### Characteristics

- Can be started or stopped
- Can be resized
- Can be terminated
- Can be replicated

> [!TIP]
> Think of an **instance** as a virtual computer running in the cloud.

---

# 7. Cluster

## Definition

A **Cluster** is a group of servers or instances working together to perform the same function.

Instead of relying on a single server, workloads are distributed across multiple instances.

### Benefits

- Higher availability
- Better performance
- Load balancing
- Fault tolerance
- Improved scalability

### Example

A website receiving millions of visitors may use a cluster of 20 web servers instead of one.

If one server fails, the others continue serving users.

---

# 8. Auto Scaling Group (ASG)

## Definition

An **Auto Scaling Group (ASG)** is a special type of cluster that automatically adjusts the number of running instances based on application demand.

### How It Works

When demand increases:

- More instances are automatically launched.

When demand decreases:

- Extra instances are automatically terminated.

### Benefits

- Reduced operational cost
- Improved application performance
- Automatic resource management
- High availability

### Example

An e-commerce website during a festival sale may scale from:

- 5 instances → 50 instances

After the sale:

- 50 instances → 5 instances

> [!IMPORTANT]
> Auto Scaling ensures applications can handle changing workloads without manual intervention.

# Servers in the Cloud

Cloud servers have transformed the way organizations deploy and manage applications.

Instead of purchasing physical hardware, organizations can provision virtual servers in minutes.

## Key Advantages

### 1. Elastic Scaling

Server capacity can be increased or decreased based on demand.

Examples:

- More CPU
- More Memory (RAM)
- Additional Storage
- More Network Bandwidth

---

### 2. Flexible Resource Allocation

Cloud servers allow organizations to:

- Upgrade memory
- Increase storage
- Add CPUs
- Expand networking resources

without replacing physical hardware.

---

### 3. Rapid Provisioning

Traditional servers may require:

- Purchasing hardware
- Shipping
- Installation
- Configuration

This process can take days or weeks.

Cloud servers can usually be created in **minutes**.

---

### 4. Reduced Capital Expenditure

Organizations do not need to purchase:

- Physical servers
- Networking equipment
- Storage devices

Instead, they rent infrastructure from cloud providers.

Benefits include:

- Lower upfront investment
- Reduced maintenance costs
- Faster deployment

---

# Security in the Cloud

Cloud providers offer extensive security controls to protect cloud resources.

Security is based on the principle of **shared responsibility**, where:

- The cloud provider secures the underlying infrastructure.
- Customers secure their applications, identities, and data.

---

## Virtual Networking

Organizations can create isolated virtual networks within the cloud.

These virtual networks behave similarly to traditional corporate networks.

### Benefits

- Better security
- Traffic isolation
- Controlled communication
- Network segmentation

---

## Public and Private Subnets

Cloud networks are often divided into:

### Public Subnet

Resources are accessible from the Internet.

Examples:

- Web servers
- Public APIs
- Load balancers

---

### Private Subnet

Resources are not directly accessible from the Internet.

Examples:

- Databases
- Internal application servers
- Backend services

Private subnets improve security by limiting external access.

---

## Secure Server Deployment

Cloud providers allow administrators to launch servers within selected networks.

This enables organizations to:

- Restrict access
- Control communication
- Protect sensitive applications
- Separate public-facing and internal resources

---

# Compute Power in the Cloud

Cloud computing provides virtually unlimited compute resources that can be allocated on demand.

Developers can build applications without worrying about purchasing hardware.

---

## Key Features

### 1. Serverless Computing

Developers write and deploy code without managing servers.

The cloud provider automatically handles:

- Infrastructure
- Operating systems
- Scaling
- Maintenance

Examples:

- AWS Lambda
- Azure Functions
- Google Cloud Functions

---

### 2. Continuous Scaling

Applications automatically scale according to demand.

Benefits include:

- Better performance
- Lower costs
- Improved user experience

---

### 3. Event-Driven Execution

Cloud platforms can execute code automatically when specific events occur.

Examples of events:

- File uploaded
- HTTP request received
- Database updated
- Message received from a queue
- Scheduled timer

This model is commonly used in serverless computing.

---

### 4. Pay Only When Code Runs

Unlike traditional servers that incur costs even when idle, serverless platforms charge only when code is actively executing.

Benefits:

- Lower operational cost
- Efficient resource utilization
- Ideal for intermittent workloads
