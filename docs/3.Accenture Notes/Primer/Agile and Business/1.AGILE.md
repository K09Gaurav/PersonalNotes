# Pre quiz
## Question 1

### Question
____________ ensures that when two different people does the work and update parallelly, one should not overwrite the other

- A. Check-out  
- B. Synchronization control  
- C. Baseline  
- D. Check-in  

---

### Answer
**B. Synchronization control**

---

### Explanation

#### Why B is Correct
Synchronization control prevents conflicts when:
- Multiple developers work on the same files
- Changes are made simultaneously
- Updates happen in parallel

Its purpose is to ensure:
- One person's work does not overwrite another's
- Version conflicts are handled properly
- Changes remain consistent

This is a core concept in configuration management systems like Git, SVN, etc.

---

#### Why A is Wrong — Check-out
Check-out means:
- Taking a copy of a file from the repository
- Making it available for editing locally

It does not itself prevent overwrite conflicts.

---

#### Why C is Wrong — Baseline
A baseline is:
- A fixed reference version of software
- A formally approved snapshot

It is not used for parallel work synchronization.

---

#### Why D is Wrong — Check-in
Check-in means:
- Uploading updated files back to the repository

It does not specifically manage simultaneous editing conflicts.

---

## Question 2

### Question
________ is the process during which the changes of a system are implemented in a controllable manner by following a predefined model, with some reasonable modifications.

- A. Update Management  
- B. Modification Management  
- C. Change Management  

---

### Answer
**C. Change Management**

---

### Explanation

#### Why C is Correct
Change Management is the formal process of:
- Handling software changes
- Approving modifications
- Tracking updates
- Implementing changes in a controlled way

Its goal is to:
- Reduce risk
- Maintain software stability
- Ensure authorized modifications only

---

#### Why A is Wrong — Update Management
"Update Management" is not the standard formal software engineering term used here.

It generally refers to applying updates, not controlling the entire change process.

---

#### Why B is Wrong — Modification Management
This is not the standard recognized term in software configuration management.

The accepted industry and academic term is:
> Change Management

## Question 5

### Question
Which is the software configuration concept that ensures that change should be done in a controlled and authorized environment

- A. SVN  
- B. Audit  
- C. Baseline  
- D. Configuration database  

---

### Answer
**C. Baseline**

---

### Explanation

#### Why C is Correct
A baseline is:
- A formally approved version of software
- A stable reference point

After a baseline is established:
- Changes cannot be made freely
- Proper approval and control are required

This ensures:
- Controlled modification
- Authorized updates only

---

#### Why A is Wrong — SVN
SVN (Subversion) is:
- A version control tool

It helps manage versions but is not the configuration management concept being asked.

---

#### Why B is Wrong — Audit
An audit is:
- A review or inspection process

It checks compliance but does not itself control changes.

---

#### Why D is Wrong — Configuration Database
A configuration database stores:
- Configuration information
- Item records
- Version details

It does not enforce authorization rules directly like baselines do.

- A. Spiral Methodology  
- B. Waterfall Methodology  
- C. Agile Methodology  
- D. Prototype Methodology  

---

#### Answer
**D. Prototype Methodology**

---

#### Explanation

#### Why D is Correct
Prototype methodology is used when:
- Requirements are unclear
- Clients are unsure of exact needs
- Frequent feedback is required

A prototype helps:
- Visualize the system early
- Clarify requirements
- Reduce misunderstandings

---

##### Why A is Wrong — Spiral Methodology

- Risk management
- Risk analysis

Prototype methodology is more specifically suited for unclear requirements.

Waterfall requires:
- Clear requirements from the beginning
- Minimal changes later

It performs poorly when requirements are unstable.

---

##### Why C is Wrong — Agile Methodology
Agile handles changing requirements effectively.

However, the question specifically emphasizes unclear requirements at the beginning, where the Prototype Model is the more direct answer.
