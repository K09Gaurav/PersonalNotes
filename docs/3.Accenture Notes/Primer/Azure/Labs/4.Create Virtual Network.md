# Azure Lab: Create a Virtual Network and Deploy Virtual Machines

## Lab Objective

In this activity, you will:

- Create a Virtual Network (VNet)
- Deploy two Virtual Machines into the same VNet
- Configure networking between the VMs
- Verify communication between the VMs

---

# Steps to Connect in Azure Portal

1. Click **Start Attempt** and wait for the environment provisioning.
2. Once the environment is created, Azure credentials will be provided.
3. Click **Generate OTP**.
4. Copy the OTP and use it to sign in to the Azure Portal.
5. Complete the activity.
6. Click **Submit Attempt**.

---

# Overview

An Azure Virtual Network (VNet) provides a private network environment for Azure resources.

In this lab, you will:

```text
Create VNet
     │
     ├── VM1
     │
     └── VM2
```

Both virtual machines will be deployed into the same network, enabling communication between them.

---

# Task 1: Create a Virtual Network

## Step 1: Sign In

Open Azure Portal:

```text
https://portal.azure.com
```

---

## Step 2: Open Virtual Networks

Navigate to:

```text
All Services
→ Virtual Networks
→ + Add
→ + Create
→ + New
```

---

## Step 3: Configure the Basics Tab

| Setting | Value |
|----------|--------|
| Subscription | Use default supplied |
| Resource Group | Use default supplied |
| Name | vnet1 |
| Region | Your nearest region |

---

## Step 4: Create the Virtual Network

1. Click **Review + Create**.
2. Wait for validation to complete.
3. Ensure validation passes.
4. Click **Create**.

---

# Task 2: Create Two Virtual Machines

## Step 1: Open Virtual Machines

Navigate to:

```text
All Services
→ Virtual Machines
→ + Add
→ + Create
→ + New
→ Virtual Machine
```

---

# Create Virtual Machine 1

## Basics Tab Configuration

| Setting | Value |
|----------|--------|
| Subscription | Use default supplied |
| Resource Group | Use default supplied |
| Virtual Machine Name | vm1xxxxx |
| Region | Your nearest region |
| Availability Options | No Infrastructure Redundancy Required |
| Security Type | Standard |
| Image | Windows Server 2025 Datacenter - x64 Gen2 |
| Size | Standard D2S V3 / Standard_DS1_V2 / Standard_B1ms |
| Username | azureuser |
| Password | Pa$$w0rd1234 |
| Public Inbound Ports | Allow Selected Ports |
| Selected Inbound Ports | RDP (3389) |

> Replace `xxxxx` with unique characters.

Example:

```text
vm11234
vm1abc1
```

---

## Networking Tab Configuration

Verify the following:

| Setting | Value |
|----------|--------|
| Virtual Network | vnet1 |
| OS Disk Type | Standard SSD |

Leave all other settings as default.

---

## Create VM1

1. Click **Review + Create**.
2. Wait for validation to pass.
3. Click **Create**.
4. Deployment typically takes **3–6 minutes**.

# Purpose of the Lab

By placing both virtual machines inside the same Virtual Network:

- They can communicate using private IP addresses.
- Network traffic remains within Azure's private network.
- Administrative access remains available through RDP.
- Applications can securely communicate without exposing internal traffic to the internet.
