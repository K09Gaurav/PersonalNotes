## Question 1

### Question
In YAML file used for BitBucket pipeline, you can use different types of container for each step by selecting different images

- A. True  
- B. False  

---

### Answer
**A. True**

---

### Explanation

#### Why True is Correct
Bitbucket Pipelines uses a YAML configuration file to define CI/CD workflows. Each step in the pipeline can use a different Docker image or container environment.

This allows:
- Different programming environments for different tasks
- Flexible execution environments
- Better dependency management

For example:
- One step may use a Java container
- Another step may use a Python container

This is a common feature in modern CI/CD systems.

---

#### Why False is Wrong
Bitbucket Pipelines does support using different images for different steps.

Therefore, saying all steps must use the same container is incorrect.

## Question 3

### Question
Each service runs in its own process and communicates with other services through a well-defined interface in Microservices

- A. True  
- B. False  

---

### Answer
**A. True**

---

### Explanation

#### Why True is Correct
Microservices architecture is based on:
- Independent services
- Separate execution processes
- Loose coupling

Each microservice:
- Performs a specific business function
- Runs independently
- Communicates using APIs or messaging systems

Common communication methods:
- REST APIs
- gRPC
- Message queues

This architecture improves:
- Scalability
- Maintainability
- Independent deployment

---

#### Why False is Wrong
If services did not run independently, the architecture would behave more like a monolithic application.

That would contradict the core principle of microservices.

## Question 5

### Question
In which of the following, there is no human intervention and only a failed test will prevent a new change to be deployed to production?

- A. Continuous Monitoring  
- B. Continuous Delivery  
- C. Continuous Integration  
- D. Continuous Deployment  

---

### Answer
**D. Continuous Deployment**

---

### Explanation

#### Why D is Correct — Continuous Deployment
Continuous Deployment is a DevOps practice where:
- Every successful code change is automatically deployed to production
- No manual approval is required
- Automated testing acts as the final checkpoint

Deployment only stops when:
- Tests fail
- Validation checks fail

This enables:
- Faster releases
- Rapid feedback
- Fully automated delivery pipelines

---

#### Why A is Wrong — Continuous Monitoring
Continuous Monitoring focuses on:
- Observing applications and infrastructure
- Detecting issues
- Tracking performance

It does not automatically deploy code changes.

---

#### Why B is Wrong — Continuous Delivery
Continuous Delivery automates:
- Build
- Test
- Deployment preparation

However, production deployment usually still requires:
- Manual approval
- Human intervention

This is the key difference from Continuous Deployment.

---

#### Why C is Wrong — Continuous Integration
Continuous Integration focuses on:
- Frequently merging code changes
- Automated builds and tests

It improves code integration quality but does not automatically deploy changes to production.
