# Pre quiz

## Question 1

### Question

Which statement is true when a DROP TABLE command is executed on a table?

- A. The DROP TABLE command can be executed on a table on which there are pending transactions.
- B. The table structure and its deleted data cannot be rolled back and restored once the DROP TABLE command is executed.
- C. Any pending transactions on the table are rolled back.
- D. Only a DBA can execute the DROP TABLE command.

---

### Answer

**B. The table structure and its deleted data cannot be rolled back and restored once the DROP TABLE command is executed.**

---

### Explanation

#### Why Correct Answer is Correct

DROP TABLE is a DDL command that removes:

- Table structure
- Table data
- Associated metadata

In most SQL exam contexts, DROP TABLE is treated as an auto-commit operation. Once executed, the table is permanently removed and cannot be restored using ROLLBACK.

---

#### Why Option A is Wrong

Whether DROP can be executed with pending transactions depends on the DBMS and transaction state. This is not universally true.

---

#### Why Option B is Wrong

This option is actually correct.

---

#### Why Option C is Wrong

Pending transactions are not automatically rolled back simply because DROP TABLE is executed.

---

#### Why Option D is Wrong

Any user with sufficient privileges can execute DROP TABLE. It is not restricted only to DBAs.

---

### Exam Tip

Remember:

- DELETE → Removes rows.
- TRUNCATE → Removes all rows.
- DROP → Removes both structure and data.

## Question 2

### Question

Which statements are true regarding constraints?

- A. A column with the UNIQUE constraint can contain NULL values.
- B. A constraint is enforced only for the INSERT operation on a table.
- C. A foreign key cannot contain NULL values.
- D. A constraint can be disabled even if the constraint column contains data.

---

### Answer

**A. A column with the UNIQUE constraint can contain NULL values.**

**D. A constraint can be disabled even if the constraint column contains data.**

---

### Explanation

#### Why Option A is Correct

UNIQUE ensures that non-null values are unique.

Most DBMSs allow NULL values in UNIQUE columns because NULL represents an unknown value.

---

#### Why Option D is Correct

Many databases allow disabling constraints even when data exists in the table.

This is often done during data migration or bulk loading.

---

#### Why Option B is Wrong

Constraints are enforced during:

- INSERT
- UPDATE

Not only during INSERT.

---

#### Why Option C is Wrong

A foreign key may contain NULL values unless a NOT NULL constraint is also applied.

---

### Exam Tip

Primary Key:

- Unique
- Not Null

Foreign Key:

- Can contain NULL

UNIQUE:

- Usually allows NULL values

## Question 3

### Question

You need to remove all the data from the employee table while leaving the table definition intact.

You want to be able to undo this operation.

How would you accomplish this task?

- A. DELETE FROM employee;
- B. DROP TABLE employee;
- C. This task cannot be accomplished.
- D. TRUNCATE TABLE employee;

---

### Answer

**A. DELETE FROM employee;**

---

### Explanation

#### Why Correct Answer is Correct

DELETE removes rows while keeping:

- Table structure
- Constraints
- Indexes

Because DELETE participates in transactions, it can be rolled back before COMMIT.

---

#### Why Option A is Wrong

This option is actually correct.

---

#### Why Option B is Wrong

DROP TABLE removes the table itself.

The structure would not remain intact.

---

#### Why Option C is Wrong

The task can absolutely be accomplished using DELETE.

---

#### Why Option D is Wrong

TRUNCATE removes all rows but generally performs an implicit commit and cannot be rolled back in typical exam scenarios.

---

### Exam Tip

If the question contains:

> "Want to undo later"

Choose:

**DELETE**

If it contains:

> "Fast removal of all rows"

Choose:

**TRUNCATE**

### Answer

Used for pattern matching.

Example concept:

- Starts with
- Ends with
- Contains

---

Used to compare a value against a list of values.

Checks whether a value belongs to a specified set.

---

Used to check whether a value lies within a range.

Range boundaries are inclusive.

---

Used to check whether a column contains a NULL value.

---

### Explanation

#### LIKE

Pattern matching operator.

Common wildcards:

- % → Any number of characters
- _ → Single character

---

#### IN

Alternative to multiple OR conditions.

---

Checks values within a specified range.

---

Used because NULL cannot be compared using = operator.

## Question 5

### Question

The SQL statements executed in a user session are:

- Create table
- Insert row 1
- Insert row 2
- SAVEPOINT A
- UPDATE row
- SAVEPOINT B
- DELETE row
- COMMIT
- DELETE row

Which statements describe the consequence of issuing:

ROLLBACK TO SAVEPOINT A

- A. Only the second DELETE statement is rolled back.
- B. Both DELETE statements and UPDATE statement are rolled back.
- C. Only the DELETE statements are rolled back.
- D. The rollback generates an error.

---

### Answer

**D. The rollback generates an error.**

---

### Explanation

#### Why Correct Answer is Correct

After SAVEPOINT A and SAVEPOINT B are created:

```text
SAVEPOINT A
UPDATE
SAVEPOINT B
DELETE
COMMIT
```

the COMMIT makes all changes permanent and removes all savepoints.

After COMMIT:

```text
DELETE FROM product WHERE pid=10;
```

is executed.

Now if:

```text
ROLLBACK TO SAVEPOINT A
```

is attempted,

SAVEPOINT A no longer exists because COMMIT erased it.

Therefore an error is generated.

---

#### Why Option A is Wrong

The savepoint no longer exists after COMMIT.

Rollback cannot selectively undo the second DELETE.

---

#### Why Option B is Wrong

The UPDATE and DELETE before COMMIT have already become permanent.

They cannot be rolled back.

---

#### Why Option C is Wrong

Neither DELETE can be rolled back using SAVEPOINT A after COMMIT.

---

#### Why Option D is Wrong

This option is actually correct.

---

### Exam Tip

COMMIT performs two important actions:

1. Makes changes permanent.
2. Removes all SAVEPOINTs.

After COMMIT:

```text
ROLLBACK TO SAVEPOINT x
```

will fail because the savepoint no longer exists.

## Question 1

### Question

How to retrieve department_id column without any duplication from employee relation?

- A. select department_id distinct from employee;
- B. select department_id from employee;
- C. select all department_id from employee;
- D. select distinct department_id from employee;

---

### Answer

**D. select distinct department_id from employee;**

---

### Explanation

#### Why Correct Answer is Correct

The DISTINCT keyword removes duplicate values from the result set.

Query:

```sql
SELECT DISTINCT department_id
FROM employee;
```

returns each department_id only once, regardless of how many employees belong to that department.

Example:

If employee table contains:

- 10
- 10
- 20
- 20
- 30

Result becomes:

- 10
- 20
- 30

---

#### Why Option A is Wrong

DISTINCT must appear immediately after SELECT.

Correct syntax:

```sql
SELECT DISTINCT column_name
FROM table_name;
```

This syntax is invalid.

---

#### Why Option B is Wrong

This returns all department_id values including duplicates.

---

#### Why Option C is Wrong

ALL is the default behavior and returns duplicates.

It does not remove repeated values.

---

### Exam Tip

Remember:

- DISTINCT → Removes duplicates.
- ALL → Returns all rows (default behavior).

## Question 2

### Question

Select the suitable option for retrieving all the employees whose last name is "kumar".

- A. select * from employee where empname like '%kumar%';
- B. select * from employee where empname like 'kumar';
- C. select * from employee where empname like 'kumar%';
- D. select * from employee where empname like '%kumar';

---

### Answer

**D. select * from employee where empname like '%kumar';**

---

### Explanation

#### Why Correct Answer is Correct

The pattern:

```sql
'%kumar'
```

means:

- Any characters before "kumar"
- Name must end with "kumar"

Examples matched:

- Raj Kumar
- Amitkumar
- Suresh Kumar

This correctly identifies names whose last part is "kumar".

---

#### Why Option A is Wrong

```sql
'%kumar%'
```

matches "kumar" anywhere in the name.

Examples:

- Kumar
- Kumaran
- Rajkumar
- Kumar Singh

The question specifically asks for last name "kumar".

---

#### Why Option B is Wrong

```sql
'kumar'
```

matches only the exact value "kumar".

Names like "Raj Kumar" would not be returned.

---

#### Why Option C is Wrong

```sql
'kumar%'
```

matches names beginning with "kumar".

Examples:

- Kumar Raj
- Kumaran

It does not ensure kumar is the last name.

---

### Exam Tip

Wildcard meanings:

- `%abc` → Ends with abc
- `abc%` → Starts with abc
- `%abc%` → Contains abc anywhere

## Question 3

### Question

Which statement about SQL is true?

- A. Date values are displayed in descending order by default.
- B. Null values are displayed first in ascending sequences.
- C. You cannot specify a column alias in an ORDER BY clause.
- D. You cannot sort query results by a column that is not included in the SELECT list.
- E. The results are sorted by the first column in the SELECT list if the ORDER BY clause is not provided.

---

### Answer

**B. Null values are displayed first in ascending sequences.**

---

### Explanation

#### Why Correct Answer is Correct

In many SQL certification and academic exam contexts (especially Oracle-style SQL questions), when sorting in ascending order:

```sql
ORDER BY column ASC
```

NULL values appear before non-null values.

Therefore the statement is considered true.

---

#### Why Option A is Wrong

Without ORDER BY, SQL does not automatically display dates in descending order.

No default descending sorting exists.

---

#### Why Option B is Wrong

This option is actually correct according to typical SQL certification expectations.

---

#### Why Option C is Wrong

Column aliases can be used in ORDER BY.

Example concept:

A column may be given an alias and then sorted using that alias.

---

#### Why Option D is Wrong

Most SQL databases allow sorting by columns not present in the SELECT list.

---

#### Why Option E is Wrong

Without ORDER BY, row order is not guaranteed.

The database may return rows in any order.

---

### Exam Tip

For certification-style SQL questions:

- ORDER BY controls sorting.
- Without ORDER BY, result order is unpredictable.
- DISTINCT removes duplicates.
- Aliases can generally be used in ORDER BY.
- Many exam platforms expect NULL values first for ascending order.

## Question 4

### Question

Select the suitable option for retrieving all the employees who have a manager?

- A. select empname, manager_id from employee where manager_id is NULL VALUE;
- B. select empname, manager_id from employee where manager_id NULL;
- C. select empname, manager_id from employee where manager_id is NULL;
- D. select empname, manager_id from employee where manager_id is NOT NULL;

---

### Answer

**D. select empname, manager_id from employee where manager_id is NOT NULL;**

---

### Explanation

#### Why Correct Answer is Correct

Employees who have a manager will have a valid value stored in the `manager_id` column.

`NOT NULL` means:

- A manager has been assigned.
- The manager_id column contains a value.

Therefore:

```sql
WHERE manager_id IS NOT NULL
```

returns employees who have managers.

---

#### Why Option A is Wrong

`IS NULL VALUE` is not valid SQL syntax.

SQL uses:

```sql
IS NULL
```

or

```sql
IS NOT NULL
```

---

#### Why Option B is Wrong

This is invalid SQL syntax.

NULL checks must use:

```sql
IS NULL
```

or

```sql
IS NOT NULL
```

---

#### Why Option C is Wrong

`IS NULL` retrieves employees who do **not** have a manager.

Typically these are top-level managers or CEOs.

---

#### Why Option D is Wrong

This option is actually correct.

---

### Exam Tip

Remember:

- `IS NULL` → No value exists.
- `IS NOT NULL` → A value exists.

For manager-related questions:

- Has manager → `IS NOT NULL`
- No manager → `IS NULL`

## Question 5

### Question

Select the suitable option for retrieving all the employees whose salary range is between 40000 and 100000?

- A. select name,salary from employee where salary between 40000 100000;
- B. select name,salary from employee where salary between 40000 and 100000;
- C. select name,salary from employee where salary is between 40000 and 100000;
- D. select name,salary from employee where salary>=40000 and salary<=100000;
- E. select name,salary from employee where salary lies between 40000 and 100000;

---

### Answer

**B. select name,salary from employee where salary between 40000 and 100000;**

**D. select name,salary from employee where salary>=40000 and salary<=100000;**

---

### Explanation

#### Why Option B is Correct

The BETWEEN operator is designed specifically for range checking.

```sql
salary BETWEEN 40000 AND 100000
```

means:

```sql
salary >= 40000
AND
salary <= 100000
```

Both limits are included.

---

#### Why Option D is Correct

This is the expanded logical equivalent of BETWEEN.

```sql
salary >= 40000
AND
salary <= 100000
```

returns exactly the same result as BETWEEN.

---

#### Why Option A is Wrong

BETWEEN requires the keyword AND.

Correct syntax:

```sql
BETWEEN value1 AND value2
```

---

#### Why Option B is Wrong

This option is actually correct.

---

#### Why Option C is Wrong

SQL does not use:

```sql
IS BETWEEN
```

This is invalid syntax.

---

#### Why Option D is Wrong

This option is actually correct.

---

#### Why Option E is Wrong

`LIES BETWEEN` is not a valid SQL operator.

SQL only supports:

```sql
BETWEEN ... AND ...
```

---

### Exam Tip

BETWEEN is inclusive.

```sql
salary BETWEEN 40000 AND 100000
```

includes:

- 40000
- 100000

Equivalent form:

```sql
salary >= 40000
AND salary <= 100000
```

Many exams treat both forms as correct when the question allows multiple answers.
