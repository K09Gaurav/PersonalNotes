# Pre quiz

## Question 1

### Question

Which tasks would require subqueries or joins in order to be performed in a single step?

- A. Listing the departments whose average commission is more than 600
- B. Finding the total commission earned by the employees in department 10
- C. Listing the employees who do not earn commission and who are working for department 20 in descending order of the employee ID
- D. Listing the employees whose annual commission is more than 6000
- E. Finding the number of employees who earn a commission that is higher than the average commission of the company
- F. Listing the employees who earn the same amount of commission as employee 3

---

### Answer

**Correct Answers:**
- E. Finding the number of employees who earn a commission that is higher than the average commission of the company
- F. Listing the employees who earn the same amount of commission as employee 3

---

### Explanation

#### Why Option E is Correct

To determine whether an employee earns more commission than the company average:

1. First calculate the average commission of all employees.
2. Then compare each employee's commission against that average.

This requires a subquery because one query's result is needed inside another query.

---

#### Why Option F is Correct

To find employees earning the same commission as employee 3:

1. First find employee 3's commission.
2. Then compare other employees' commissions against that value.

This also requires a subquery (or self-join).

---

#### Why Option A is Wrong

This can be solved using:

- GROUP BY
- HAVING

No subquery is required.

---

#### Why Option B is Wrong

This requires only:

- WHERE department_id = 10
- SUM(commission)

No subquery or join is needed.

---

#### Why Option C is Wrong

Simple filtering and sorting can solve this.

No subquery is required.

---

#### Why Option D is Wrong

Annual commission can be calculated directly as:

Monthly Commission × 12

No subquery is required.

---

### Exam Tip

Subqueries are commonly needed when:

- Comparing against averages
- Comparing against another row's value
- Using results of one query inside another

## Question 2

### Question

To create a report displaying employee last names, department names, and locations. Which query should you use to create an equi-join?

- A.

SELECT employees.last_name, departments.department_name, departments.location_id
FROM employees e, departments d
WHERE e.department_id = d.department_id;

- B.

SELECT e.last_name, d.department_name, d.location_id
FROM employees e, departments d
WHERE manager_id = manager_id;

- C.

SELECT e.last_name, d.department_name, d.location_id
FROM employees e, departments d
WHERE e.department_id = d.department_id;

- D.

SELECT last_name, department_name, location_id
FROM employees, departments;

---

### Answer

**C. SELECT e.last_name, d.department_name, d.location_id FROM employees e, departments d WHERE e.department_id = d.department_id;**

---

### Explanation

#### Why Correct Answer is Correct

An equi-join joins two tables using equality (=).

The relationship between Employees and Departments is:

```text
employees.department_id = departments.department_id
```

Option C correctly:

- Uses aliases e and d
- Uses the join condition
- Retrieves data from both tables

---

#### Why Option A is Wrong

The aliases e and d are declared but the SELECT clause refers to full table names.

Many exam platforms treat this as incorrect usage.

---

#### Why Option B is Wrong

```text
manager_id = manager_id
```

is always true.

This produces a Cartesian product instead of a proper join.

---

#### Why Option C is Wrong

This option is actually correct.

---

#### Why Option D is Wrong

No join condition is provided.

This produces a Cartesian product.

---

### Exam Tip

Equi-join pattern:

```text
table1.column = table2.column
```

Without a join condition, every row of one table combines with every row of the other table.

## Question 3

### Question

Which statement would display the highest credit limit available in each income level in each city in the Customers table?

- A.

SELECT cust_city, cust_income_level, MAX(cust_credit_limit)
FROM customers
GROUP BY cust_city, cust_income_level, MAX(cust_credit_limit);

- B.

SELECT cust_city, cust_income_level, MAX(cust_credit_limit)
FROM customers
GROUP BY cust_city, cust_income_level;

- C.

SELECT cust_city, cust_income_level, MAX(cust_credit_limit)
FROM customers
GROUP BY cust_credit_limit, cust_income_level, cust_city;

- D.

SELECT cust_city, cust_income_level, MAX(cust_credit_limit)
FROM customers
GROUP BY cust_city, cust_income_level, cust_credit_limit;

---

### Answer

**B. SELECT cust_city, cust_income_level, MAX(cust_credit_limit) FROM customers GROUP BY cust_city, cust_income_level;**

---

### Explanation

#### Why Correct Answer is Correct

The report requires:

- City
- Income Level
- Highest Credit Limit

MAX() is an aggregate function.

The non-aggregated columns:

- cust_city
- cust_income_level

must appear in GROUP BY.

Therefore:

```text
GROUP BY cust_city, cust_income_level
```

is correct.

---

#### Why Option A is Wrong

Aggregate functions cannot appear inside GROUP BY.

---

#### Why Option B is Wrong

This option is actually correct.

---

#### Why Option C is Wrong

Grouping by cust_credit_limit defeats the purpose of finding a maximum value.

---

#### Why Option D is Wrong

Including cust_credit_limit in GROUP BY again prevents proper aggregation.

---

### Exam Tip

Rule:

Every column in SELECT that is not inside an aggregate function must appear in GROUP BY.

## Question 5

### Question

What statement would display the age of Customers with the alias name as AGE?

- A.

select round((curdate()-Birth_date)/365) AGE from customer;

- B.

select (start_date-curdate())/365 AGE from customer;

- C.

select round((birth_date)-Birth_date)/365 from customer;

- D.

select (Birth_date/365) AGE from customer;

---

### Answer

**A. select round((curdate()-Birth_date)/365) AGE from customer;**

---

### Explanation

#### Why Correct Answer is Correct

Age is calculated using:

```text
Current Date − Birth Date
```

The result gives the number of days.

Dividing by 365 converts days into years.

ROUND() is used to display a whole-number age.

The alias:

```text
AGE
```

renames the resulting column.

---

#### Why Option A is Wrong

This option is actually correct.

---

#### Why Option B is Wrong

Uses start_date instead of birth_date.

The question asks for customer age.

---

#### Why Option C is Wrong

birth_date minus birth_date equals zero.

The result would always be zero.

---

#### Why Option D is Wrong

A date cannot be meaningfully converted to age by simply dividing it by 365.

---

### Exam Tip

Common age-calculation logic:

```text
Current Date − Birth Date
```

Then convert the result into years using division or date functions.

## Question 1

### Question

To display the names of employees who earn more than the average salary of all employees.

```sql
SELECT last_name, first_name
FROM employee
WHERE salary > AVG(salary);
```

Which change should you make to achieve the desired results?

- A. Move the function to the SELECT clause and add a GROUP BY clause.
- B. Move the function to the SELECT clause and add a GROUP BY clause and a HAVING clause.
- C. Change the function in the WHERE clause.
- D. Use a subquery in the WHERE clause to compare the average salary value.

---

### Answer

**D. Use a subquery in the WHERE clause to compare the average salary value.**

---

### Explanation

#### Why Correct Answer is Correct

Aggregate functions such as AVG() cannot be used directly in a WHERE clause because WHERE filters rows before aggregation occurs.

To compare each employee's salary against the overall average salary:

1. First calculate the average salary.
2. Then compare each employee's salary with that result.

This requires a subquery.

The logical process is:

- Calculate average salary of all employees.
- Return employees whose salary is greater than that average.

This is one of the most common uses of subqueries.

---

#### Why Option A is Wrong

Moving AVG() to the SELECT clause only displays the average.

It does not filter employees earning above average.

---

#### Why Option B is Wrong

GROUP BY and HAVING are used for grouped results.

The requirement is to compare each employee against a company-wide average.

---

#### Why Option C is Wrong

Simply changing the function does not solve the problem that aggregate functions cannot be directly used in WHERE.

---

#### Why Option D is Wrong

This option is actually correct.

---

### Exam Tip

Whenever a question says:

- Greater than average
- Less than average
- Equal to maximum
- Equal to minimum

A subquery is often required.

## Question 3

### Question

Which operator is NOT appropriate in the join condition of a non-equi join SELECT statement?

- A. IN operator
- B. LIKE operator
- C. BETWEEN x AND y operator
- D. equal operator
- E. greater than or equal to operator

---

### Answer

**D. equal operator**

---

### Explanation

#### Why Correct Answer is Correct

A non-equi join uses comparison operators other than equality.

Examples:

- >
- <
- >=
- <=
- BETWEEN

If the operator used is "=" then the join becomes an equi-join.

Therefore "=" is not appropriate for a non-equi join.

---

#### Why Option A is Wrong

IN can be used in certain join-related filtering situations.

It is not the defining characteristic of a non-equi join but is not the incorrect answer here.

---

#### Why Option B is Wrong

LIKE can be used for pattern-based matching.

---

#### Why Option C is Wrong

BETWEEN is one of the most common non-equi join operators.

---

#### Why Option D is Wrong

This option is actually correct.

---

#### Why Option E is Wrong

>= is a valid non-equi join operator.

---

### Exam Tip

Remember:

- Equi Join → =
- Non-Equi Join → >, <, >=, <=, BETWEEN

## Question 4

### Question

In which cases would you use an outer join?

- A. The tables being joined have NOT NULL columns.
- B. The tables being joined have only matched data.
- C. Only when the tables have a primary key/foreign key relationship.
- D. The tables being joined have both matched and unmatched data.
- E. The tables being joined have only unmatched data.

---

### Answer

**D. The tables being joined have both matched and unmatched data.**

---

### Explanation

#### Why Correct Answer is Correct

An outer join returns:

- Matching rows
- Non-matching rows from one or both tables

This is the primary purpose of outer joins.

Examples:

- LEFT OUTER JOIN
- RIGHT OUTER JOIN
- FULL OUTER JOIN

Outer joins help preserve rows that would otherwise be lost in an inner join.

---

#### Why Option A is Wrong

NOT NULL columns do not determine whether an outer join is needed.

---

#### Why Option B is Wrong

If only matched data is required, an INNER JOIN is sufficient.

---

#### Why Option C is Wrong

Outer joins are not restricted to PK-FK relationships.

---

#### Why Option D is Wrong

This option is actually correct.

---

#### Why Option E is Wrong

Outer joins are generally used when both matching and non-matching rows are important.

---

### Exam Tip

INNER JOIN:

- Only matching rows

OUTER JOIN:

- Matching rows
- Plus unmatched rows

## Question 5

### Question

In which two cases would you use the USING clause? (Choose two)

- A. The tables to be joined have multiple NULL columns.
- B. You want to create a nonequijoin.
- C. The tables to be joined have columns with the same name and compatible data types.
- D. The tables to be joined have columns of the same name and different data types.

---

### Answer

**C. The tables to be joined have columns with the same name and compatible data types.**

**D. The tables to be joined have columns of the same name and different data types.**

---

### Explanation

#### Why Option C is Correct

The `USING` clause is commonly used when the columns involved in the join have the same name in both tables.

This simplifies the join syntax because SQL automatically understands that the columns with the same name are the join columns.

Example concept:

- Employee.department_id
- Department.department_id

Since both columns share the same name, the `USING` clause can be applied.

For exam purposes, this is the primary condition for using `USING`.

---

#### Why Option D is Correct

The quiz platform expects this option as correct.

The reasoning used by the platform is that the columns involved in the join have the same name.

In real-world SQL systems, the data types generally need to be compatible or implicitly convertible. However, this training platform focuses mainly on the identical column-name requirement and therefore accepts this option.

---

#### Why Option A is Wrong

The existence of NULL values in columns has no relationship with the `USING` clause.

`USING` is based on join-column names, not on whether columns contain NULL values.

---

#### Why Option B is Wrong

`USING` is designed for equi-joins.

A non-equi join uses operators such as:

- Greater than (`>`)
- Less than (`<`)
- Greater than or equal to (`>=`)
- Less than or equal to (`<=`)
- BETWEEN

Therefore `USING` is not suitable for a non-equi join.

---

### Exam Tip

For this quiz platform:

- Same column names → `USING` clause
- Expected answers → **C and D**

Practical SQL knowledge:

Most database systems expect the columns used in a `USING` clause to have compatible data types in addition to having the same name.
