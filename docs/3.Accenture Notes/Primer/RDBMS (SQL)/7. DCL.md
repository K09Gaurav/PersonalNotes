# Pre quiz

## Question 1

### Question

_____ is used to retrieve records that do not meet the join condition.

- A. Outer Join
- B. Non Equi Join
- C. Self Join
- D. Equi Join

---

### Answer

**A. Outer Join**

---

### Explanation

#### Why Correct Answer is Correct

An Outer Join retrieves:

- Matching rows between tables
- Unmatched rows from one or both tables

This is the key difference between an Inner Join and an Outer Join.

Outer joins are useful when you want to see records even if there is no corresponding match in the other table.

Types of Outer Joins:

- Left Outer Join
- Right Outer Join
- Full Outer Join

---

#### Why Option A is Correct

Outer Join includes unmatched records in the result set.

---

#### Why Option B is Wrong

A Non Equi Join uses operators such as:

- >
- <
- >=
- <=
- BETWEEN

It is not specifically used to retrieve unmatched records.

---

#### Why Option C is Wrong

A Self Join joins a table with itself.

Its purpose is unrelated to unmatched records.

---

#### Why Option D is Wrong

An Equi Join returns only matching rows based on equality conditions.

---

### Exam Tip

Remember:

- Inner/Equi Join → Matching rows only
- Outer Join → Matching + Unmatched rows

## Question 2

### Question

Joining a table to itself is called as ______.

- A. Equi Join
- B. Self Join
- C. Non Equi Join
- D. Outer Join

---

### Answer

**B. Self Join**

---

### Explanation

#### Why Correct Answer is Correct

A Self Join occurs when a table is joined with itself.

This is commonly used when rows within the same table are related.

Examples:

- Employee and Manager relationships
- Parent-child relationships

Although the same table is used twice, aliases are generally used to distinguish the two logical copies.

---

#### Why Option A is Wrong

An Equi Join refers to the equality condition used in a join.

It does not necessarily involve the same table.

---

#### Why Option B is Correct

A Self Join specifically means joining a table to itself.

---

#### Why Option C is Wrong

A Non Equi Join uses non-equality operators.

---

#### Why Option D is Wrong

An Outer Join retrieves unmatched records.

---

### Exam Tip

Keyword:

**Table joined with itself → Self Join**

## Question 3

### Question

The _______ join is based on all columns in the two tables that have the same data type.

- A. Cross
- B. Full Outer
- C. Natural
- D. Left Outer

---

### Answer

**C. Natural**

---

### Explanation

#### Why Correct Answer is Correct

A Natural Join automatically joins tables using columns that:

- Have the same name
- Have compatible data types

The database automatically determines the join columns.

No explicit join condition is required.

---

#### Why Option A is Wrong

A Cross Join produces a Cartesian product.

It does not depend on matching columns.

---

#### Why Option B is Wrong

A Full Outer Join returns all matched and unmatched rows.

Column similarity is not its defining feature.

---

#### Why Option C is Correct

Natural Join automatically identifies common columns and joins them.

---

#### Why Option D is Wrong

A Left Outer Join returns all rows from the left table regardless of matching.

---

### Exam Tip

Natural Join:

- Automatically finds common columns
- No explicit ON condition required

## Question 4

### Question

The _______ join produces the cross product of two tables.

- A. Cross
- B. Equi
- C. Self
- D. Outer

---

### Answer

**A. Cross**

---

### Explanation

#### Why Correct Answer is Correct

A Cross Join produces every possible combination of rows from two tables.

If:

- Table A contains 5 rows
- Table B contains 10 rows

Result:

- 5 × 10 = 50 rows

This is known as the Cartesian Product.

---

#### Why Option A is Correct

Cross Join creates the Cartesian product.

---

#### Why Option B is Wrong

Equi Join returns only matching rows.

---

#### Why Option C is Wrong

Self Join joins a table with itself.

---

#### Why Option D is Wrong

Outer Join returns matched and unmatched rows.

---

### Exam Tip

Cross Join = Cartesian Product

## Question 5

### Question

Equijoin is called as ______.

- A. Equal Join
- B. Outer Join
- C. Self Join
- D. Simple Join

---

### Answer

**D. Simple Join**

---

### Explanation

#### Why Correct Answer is Correct

An Equi Join is a join where the join condition uses the equality operator (=).

Many database textbooks and training platforms refer to it as a **Simple Join**.

Example concept:

- Employee.department_id = Department.department_id

Since equality is used, it becomes an Equi Join.

---

#### Why Option A is Wrong

Although "Equal Join" sounds logical, it is not the standard term used in SQL.

---

#### Why Option B is Wrong

Outer Join retrieves unmatched records.

---

#### Why Option C is Wrong

Self Join joins a table to itself.

---

#### Why Option D is Correct

Many academic SQL materials use the term **Simple Join** as another name for Equi Join.

---

### Exam Tip

Platform expectation:

- Equi Join = Simple Join

Practical SQL discussions often use the term **Equi Join** directly rather than **Simple Join**.

# Post Quiz

## Question 1

### Question

```sql
CREATE INDEX emp_dept_id_idx
ON employee(dept_id);
```

Which of the following statements are true with respect to the above index?

- A. Store an index in the EMPLOYEE table.
- B. Override the unique index created when the FK relationship was defined.
- C. May reduce the amount of disk I/O for SELECT statements.
- D. Increase the chance of full table scans.
- E. May reduce the amount of disk I/O for INSERT statements.

---

### Answer

**C. May reduce the amount of disk I/O for SELECT statements.**

---

### Explanation

#### Why Correct Answer is Correct

Indexes are created to improve data retrieval performance.

When a query searches using the indexed column:

- Fewer data blocks need to be read.
- The database can locate rows faster.
- Disk I/O is reduced.

As a result, SELECT statements that use the indexed column often execute more efficiently.

---

#### Why Option A is Wrong

An index is a separate database object.

It is not stored as part of the table itself.

---

#### Why Option B is Wrong

Foreign keys do not automatically create or override unique indexes.

This statement is incorrect.

---

#### Why Option C is Correct

Indexes help the database locate records quickly, reducing disk reads during retrieval.

---

#### Why Option D is Wrong

Indexes usually reduce the need for full table scans.

They do not increase the likelihood of full table scans.

---

#### Why Option E is Wrong

Indexes can actually make INSERT operations slower because the index must also be updated.

---

### Exam Tip

Indexes generally:

- Improve SELECT performance
- May slow INSERT, UPDATE, and DELETE operations

## Question 4

### Question

The owner has all the privileges on the object.

- A. True
- B. False

---

### Answer

**True**

---

### Explanation

#### Why True is Correct

When a user creates a database object:

- Table
- View
- Index
- Procedure

that user becomes the owner.

The owner automatically possesses all privileges on that object.

---

#### Why False is Wrong

Ownership inherently grants full control over the object.

Therefore the statement is true.

---

### Exam Tip

Object Creator = Object Owner

Owner automatically receives all privileges.

## Question 5

### Question

An owner can give specific privileges on the owner's objects to others.

- A. True
- B. False

---

### Answer

**True**

---

### Explanation

#### Why True is Correct

Owners can use the GRANT statement to provide privileges such as:

- SELECT
- INSERT
- UPDATE
- DELETE

to other users.

This is a fundamental feature of database security.

---

#### Why False is Wrong

Object owners are specifically allowed to grant privileges to other users.

Therefore the statement is false.

---

### Exam Tip

Important commands:

- GRANT → Give privileges
- REVOKE → Remove privileges

Object owners can generally grant privileges on objects they own.
