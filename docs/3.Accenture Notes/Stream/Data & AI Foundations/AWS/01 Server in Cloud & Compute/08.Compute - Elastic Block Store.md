# Introduction

**Amazon Elastic Block Store (Amazon EBS)** is AWS's **block-level storage service** designed primarily for **Amazon EC2 instances**. It provides persistent storage volumes that can be attached to virtual machines, functioning similarly to a physical hard drive attached to a computer.

EBS volumes are commonly used to store:

- Operating systems
- Application files
- Databases
- User data
- Log files

> [!IMPORTANT]
> **Amazon EBS = Persistent Block Storage for EC2 Instances**

---

# What is Amazon EBS?

## Definition

**Amazon Elastic Block Store (EBS)** is a **persistent block storage service** that provides virtual storage volumes for Amazon EC2 instances.

These storage volumes behave like physical hard drives and can be attached, detached, backed up, and resized as needed.

Unlike temporary storage, data stored on an EBS volume remains available even if the EC2 instance is stopped or terminated (unless configured to delete on termination).

---

# How EBS Works

An EBS volume is created separately from an EC2 instance and then attached to it.

Before it can store data, the volume typically needs to be:

1. Created
2. Attached to an EC2 instance
3. Formatted (if new)
4. Mounted to the operating system

```text
        Amazon EC2 Instance
      +----------------------+
      |      Operating       |
      |      System          |
      +----------+-----------+
                 |
                 |
         Attached EBS Volume
      +----------------------+
      | Persistent Storage   |
      | Files, Logs, DB      |
      +----------------------+
```

---

# Why Use Amazon EBS?

Without EBS, an EC2 instance may only have temporary storage (Instance Store).

EBS provides:

- Persistent storage
- High durability
- Flexible storage sizes
- Backup capabilities
- Easy scalability

It is the preferred storage option for most production EC2 workloads.

---

# Features of Amazon EBS

## 1. Persistent Storage

Data stored on an EBS volume remains intact even if:

- The EC2 instance is stopped.
- The EC2 instance is rebooted.
- The EC2 instance is terminated (provided the volume is configured to persist).

This makes EBS suitable for long-term storage.

---

## 2. Block-Level Storage

EBS stores data as **blocks**, similar to a traditional hard disk.

Operating systems view an EBS volume just like a local disk.

This makes it suitable for:

- Databases
- Operating systems
- Applications
- File systems

---

## 3. Attachable Storage

EBS volumes can be:

- Attached to an EC2 instance.
- Detached from an EC2 instance.
- Reattached to another compatible EC2 instance (within the same Availability Zone).

This provides flexibility when replacing or migrating servers.

---

## 4. High Availability

Every EBS volume is **automatically replicated within its Availability Zone (AZ)**.

If one storage component fails, AWS uses the replicated copy to maintain availability.

> [!TIP]
> EBS replication occurs **within a single Availability Zone**, not across multiple AZs.

---

## 5. Durability

Automatic replication protects data against hardware failures.

This improves:

- Reliability
- Availability
- Data protection

---

## 6. Scalable Storage

EBS volumes can often be modified without recreating them.

You can increase:

- Storage size
- Performance
- Volume type

This allows applications to grow without major downtime.

---

# EBS Volume Types

AWS offers different EBS volume types based on workload requirements.

They are broadly divided into two categories.

---

## 1. Solid State Drives (SSD)

Optimized for workloads requiring:

- Low latency
- High IOPS (Input/Output Operations Per Second)
- Fast performance

Common use cases:

- Databases
- Boot volumes
- Enterprise applications

---

## 2. Hard Disk Drives (HDD)

Optimized for:

- Large sequential reads/writes
- Lower storage cost
- High throughput

Common use cases:

- Big data
- Log storage
- Backups
- Streaming workloads

---

# Types of Storage in EC2

An EC2 instance can use two different storage options.

## Instance Store (Ephemeral Storage)

- Temporary storage
- Data is lost if the instance is terminated
- Very fast
- Best for temporary data

---

## Amazon EBS

- Persistent storage
- Data survives instance stop/restart
- Can survive termination (if configured)
- Ideal for production workloads

---

# Instance Store vs Amazon EBS

| Feature | Instance Store | Amazon EBS |
|----------|----------------|------------|
| Storage Type | Temporary (Ephemeral) | Persistent |
| Data After Stop | May be retained depending on instance, but not guaranteed for lifecycle events | Retained |
| Data After Termination | Lost | Can be retained if Delete on Termination is disabled |
| Can Detach & Reattach | No | Yes |
| Suitable For | Temporary Cache, Scratch Data | Databases, OS, Applications |
| Replicated | No | Yes (within AZ) |

> [!IMPORTANT]
> **Use EBS whenever your data must survive beyond the life of an EC2 instance.**

---

# EBS Snapshots

Amazon EBS supports **Snapshots**, which are point-in-time backups of an EBS volume.

Snapshots are stored in Amazon S3 (managed internally by AWS).

They are useful for:

- Backup
- Disaster recovery
- Migration
- Creating new volumes

> [!NOTE]
> A snapshot captures the state of the volume at a specific moment.

# Benefits of Amazon EBS

- Persistent storage
- High availability
- Automatic replication within an AZ
- Scalable storage capacity
- Reliable performance
- Easy backup using snapshots

---

# Limitations

- Can only be attached to EC2 instances within the same Availability Zone.
- Separate charges apply for storage and snapshots.
- Performance depends on the selected volume type.

---

# Important Notes

> [!TIP]
> Think of an EBS volume as an **external hard drive** connected to a virtual server. You can attach it, detach it, back it up, and continue using your data even after replacing the server.

---

> [!WARNING]
> Although EBS data is replicated within an Availability Zone, it is **not automatically replicated across Availability Zones**. Use **Snapshots** or other AWS services if cross-AZ or cross-region protection is required.

# Memory Trick

> [!TIP]
> Imagine an **EC2 instance as a desktop computer**:
>
> - **Instance Store** is like **RAM** or a temporary USB drive—fast but not reliable for long-term storage.
> - **Amazon EBS** is like a **hard disk or SSD** permanently attached to the computer.
>
> Even if you replace the computer, you can remove the hard disk (EBS volume) and attach it to another machine, keeping all your data intact.

# Interview One-Liners

**Amazon EBS**
> Amazon Elastic Block Store (EBS) is a persistent block storage service designed for use with Amazon EC2 instances.

**Block Storage**
> A storage architecture where data is stored in fixed-size blocks and presented to the operating system like a physical disk.

**Persistent Storage**
> Storage that retains data independently of the lifecycle of the compute instance using it.

**EBS Volume**
> A virtual hard disk that can be attached to an EC2 instance to provide persistent storage.

**EBS Snapshot**
> A point-in-time backup of an EBS volume used for backup, recovery, and migration.

**Instance Store**
> Temporary storage physically attached to the host machine that is lost when the instance is terminated.
