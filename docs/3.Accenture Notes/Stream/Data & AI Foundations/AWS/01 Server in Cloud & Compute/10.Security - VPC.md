# Virtual Private Cloud (VPC)

---

# Introduction

**Amazon Virtual Private Cloud (Amazon VPC)** is a networking service that allows you to create a **logically isolated private network** within the AWS Cloud.

You can launch AWS resources such as:

- Amazon EC2
- Amazon RDS
- Elastic Load Balancer
- NAT Gateway
- Lambda (VPC-enabled)
- Other AWS networking resources

inside your VPC while having complete control over networking and security.

> [!IMPORTANT]
> **Amazon VPC = Your own private network inside AWS.**

---

# What is a VPC?

A **Virtual Private Cloud (VPC)** is a logically isolated section of the AWS Cloud where you can securely deploy AWS resources.

Unlike traditional on-premises networks, AWS manages the underlying infrastructure while you control the virtual network.

Each VPC belongs to a **single AWS account** and is isolated from VPCs in other AWS accounts unless explicitly connected.

---

# Why Do We Need a VPC?

A VPC provides a secure environment for deploying cloud resources.

It allows you to:

- Deploy servers securely
- Isolate applications
- Control network traffic
- Define private IP ranges
- Separate public and private resources
- Secure sensitive workloads

Example:

- Web Server → Public Subnet
- Database Server → Private Subnet

---

# VPC Scope

A VPC spans **all Availability Zones (AZs)** within a single AWS Region.

```text
AWS Region
│
├── Availability Zone A
│      ├── Public Subnet
│      └── Private Subnet
│
├── Availability Zone B
│      ├── Public Subnet
│      └── Private Subnet
│
└── Same VPC
```

---

# What Can You Control in a VPC?

Amazon VPC gives complete control over your virtual networking environment.

You can configure:

- IP Address Range (CIDR Block)
- Subnets
- Route Tables
- Internet Gateway
- NAT Gateway
- Network ACLs
- Security Groups

---

# Key Components of a VPC

## 1. CIDR Block

Defines the private IP address range available inside the VPC.

Example:

```text
10.0.0.0/16
```

Every EC2 instance launched inside the VPC receives a private IP from this range.

---

## 2. Subnets

A subnet is a smaller network created inside a VPC.

Types:

- Public Subnet
- Private Subnet

---

## 3. Route Tables

A Route Table determines how network traffic is routed.

It defines where packets should go.

Examples:

- Internet Gateway
- NAT Gateway
- Local VPC
- VPN Connection

---

## 4. Internet Gateway (IGW)

Allows communication between the VPC and the Internet.

Characteristics:

- One Internet Gateway per VPC
- Required for Public Subnets
- Enables inbound and outbound Internet connectivity

---

## 5. NAT Gateway

Allows resources in a **Private Subnet** to access the Internet **without exposing them to inbound Internet traffic**.

Common use:

- OS Updates
- Package Downloads
- Software Installation

---

# Default VPC

Every AWS account automatically receives a **Default VPC** in each Region.

Characteristics:

- Already configured
- Public Subnets available
- Internet Gateway attached
- Auto-assigns public IPs (default behavior)

> [!TIP]
> Beginners usually launch EC2 instances in the **Default VPC** because it requires minimal setup.

---

# Custom VPC

You can also create your own VPC.

In a Custom VPC, you choose:

- CIDR Block
- Subnets
- Route Tables
- Gateways
- Security Configuration

---

# VPC Limits

By default:

- **5 VPCs per AWS Region per AWS Account**

If more are required, request an increase through:

- AWS Service Quotas
- AWS Support

---

# VPC Pricing

Creating and using a VPC itself is **free**.

However, resources created inside the VPC (such as EC2 instances, NAT Gateways, etc.) may incur charges.

---

# Amazon S3 and VPC

You can restrict access to Amazon S3 so that it is accessible only from resources inside your VPC using VPC Endpoints.

This improves security by preventing public Internet access.

---

# CIDR Block

## What is a CIDR Block?

A **CIDR (Classless Inter-Domain Routing)** block defines the range of private IP addresses available within a VPC.

Format:

```text
IP Address/Prefix Length
```

Example:

```text
10.0.0.0/16
```

---

## Common Private CIDR Blocks (RFC 1918)

| CIDR Block | Private IP Range |
|------------|------------------|
| `10.0.0.0/8` | 10.0.0.0 – 10.255.255.255 |
| `172.16.0.0/12` | 172.16.0.0 – 172.31.255.255 |
| `192.168.0.0/16` | 192.168.0.0 – 192.168.255.255 |

These ranges are reserved for private networks and are commonly used when creating VPCs.

---

# VPC vs VPN

| VPC | VPN |
|-----|-----|
| Private virtual network in AWS | Secure encrypted connection over the Internet |
| Hosts AWS resources | Connects users or networks securely |
| Controls networking, routing, and subnets | Encrypts traffic between endpoints |
| Exists inside AWS | Connects external devices to a network |

---

# IP Address

An **IP Address** uniquely identifies a device on a network.

Examples of devices:

- Computer
- Server
- Printer
- EC2 Instance

Without an IP address, devices cannot communicate over a network.

---

# Types of IP Addresses

## IPv4

- 32-bit address
- 4 octets
- Decimal format

Example:

```text
192.168.1.1
```

Total possible addresses:

```text
2³² = 4,294,967,296
```

---

## IPv6

- 128-bit address
- 8 hextets
- Hexadecimal format

Example:

```text
2001:0db8:85a3::1
```

Total possible addresses:

```text
2¹²⁸
```

Provides a vastly larger address space than IPv4.

---

# IPv4 Address Classes

| Class | Address Range | Default Mask | Purpose |
|--------|---------------|--------------|---------|
| A | 0.0.0.0 – 127.255.255.255 | /8 | Large Networks |
| B | 128.0.0.0 – 191.255.255.255 | /16 | Medium Networks |
| C | 192.0.0.0 – 223.255.255.255 | /24 | Small Networks |
| D | 224.0.0.0 – 239.255.255.255 | N/A | Multicast |
| E | 240.0.0.0 – 255.255.255.255 | N/A | Reserved |

---

# Public vs Private IP Addresses

## Public IP

- Globally unique
- Accessible over the Internet
- Assigned by AWS for Internet-facing resources

---

## Private IP

- Used within private networks
- Not directly accessible from the Internet
- Assigned from the VPC's CIDR block

---

# Public and Private Subnets

## Public Subnet

Characteristics:

- Connected to an Internet Gateway
- Resources can communicate with the Internet
- Typically hosts Web Servers, Bastion Hosts, Load Balancers

---

## Private Subnet

Characteristics:

- No direct Internet access
- Uses a NAT Gateway for outbound Internet access
- Typically hosts Databases, Application Servers, Internal Services

---

# Typical VPC Architecture

```text
                    Internet
                        │
                Internet Gateway
                        │
              Public Route Table
                        │
        +-------------------------------+
        |         Public Subnet         |
        |      Web Server (EC2)         |
        +-------------------------------+
                        │
                 NAT Gateway
                        │
             Private Route Table
                        │
        +-------------------------------+
        |        Private Subnet         |
        |     Database Server (RDS)     |
        +-------------------------------+
```

---

# Bastion Host (Jump Server)

A **Bastion Host** is an EC2 instance placed in a **Public Subnet** that provides secure administrative access to resources in a **Private Subnet**.

Typical flow:

```text
Administrator
      │
      ▼
Public EC2 (Bastion Host)
      │
      ▼
Private EC2
```

Only the Bastion Host is exposed to the Internet, while private instances remain inaccessible from outside the VPC.

---

# Important Notes

> [!IMPORTANT]
> Every VPC must have a **CIDR block** that defines the range of private IP addresses available for resources within that VPC.

> [!NOTE]
> AWS automatically creates a **Default VPC** in each Region for new accounts, making it easier to launch resources without manual network configuration.

> [!TIP]
> A common production architecture is to place **Web Servers** in a Public Subnet and **Databases** in a Private Subnet for improved security.

# Quick Revision

- VPC = Private virtual network in AWS
- Spans all Availability Zones within a Region
- Uses a CIDR block to define its private IP range
- Contains Public and Private Subnets
- Internet Gateway enables Internet access
- NAT Gateway provides outbound Internet access for Private Subnets
- Default limit: **5 VPCs per Region**
- Default VPC is automatically created for each Region

# Memory Trick

> [!TIP]
> Think of a **VPC as a gated residential society**:
>
> - **VPC** → The society
> - **CIDR Block** → Plot numbers available in the society
> - **Subnets** → Different blocks or sectors
> - **Public Subnet** → Shops and visitor area (accessible from outside)
> - **Private Subnet** → Residential area (restricted access)
> - **Internet Gateway** → Main entrance gate
> - **NAT Gateway** → Delivery exit that lets residents go out but prevents outsiders from entering directly

# Interview One-Liners

**Amazon VPC**  
> Amazon Virtual Private Cloud (VPC) is a logically isolated virtual network in AWS where you can securely launch and manage AWS resources.

**CIDR Block**  
> A CIDR block defines the range of private IP addresses available within a VPC.

**Public Subnet**  
> A subnet with a route to an Internet Gateway, allowing resources to communicate with the Internet.

**Private Subnet**  
> A subnet without direct Internet access, typically used for internal resources such as databases.

**Internet Gateway (IGW)**  
> A highly available AWS-managed gateway that enables communication between a VPC and the Internet.

**NAT Gateway**  
> An AWS-managed service that allows resources in private subnets to access the Internet without allowing inbound Internet connections.

**Bastion Host**  
> A secure EC2 instance in a public subnet used to administer instances in private subnets.
