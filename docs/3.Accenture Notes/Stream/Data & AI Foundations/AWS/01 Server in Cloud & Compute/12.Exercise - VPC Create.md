# Lab: Create a Custom VPC for an Elastic Beanstalk Application

## Objective

Create the minimum networking infrastructure required to deploy an **Elastic Beanstalk (EC2-based)** web application.

---

# Target Architecture

The completed VPC should contain:

- One VPC
- One Public Subnet
- One Internet Gateway
- One Route Table with Internet access

![Pasted image 20260728230506](../../../images/Pasted%20image%2020260728230506.png)

---

# Required Components

- VPC
- Public Subnet
- Internet Gateway (IGW)
- Route Table
- Default Route (`0.0.0.0/0 → Internet Gateway`)

---

# Option 1 - Create All Components at Once

AWS provides the **VPC and More** option to automatically create the required networking components.

## Configuration

| Setting | Value |
|---------|-------|
| Create Resources | **VPC and More** |
| IPv4 CIDR | `10.0.0.0/24` |
| Availability Zones | **1** |
| Public Subnets | **1** |
| Private Subnets | **0** |
| NAT Gateway | **None** |
| VPC Endpoints | **None** |
| DNS Hostnames | **Disabled** |
| DNS Resolution | **Disabled** |

![Pasted image 20260728230521](../../../images/Pasted%20image%2020260728230521.png)

> **Note:** This option automatically creates the required networking resources in a single step.

---

# Option 2 - Create Components Manually

This option creates each networking component individually to better understand how a VPC is built.

---

# Step 1 - Create the VPC

1. Open the **VPC Dashboard**.
2. Click **Create VPC**.
3. Select:

```text
VPC only
```

4. Enter a **Name Tag**.
5. Set the IPv4 CIDR block:

```text
10.0.0.0/24
```

6. Click **Create VPC**.

![Pasted image 20260728230535](../../../images/Pasted%20image%2020260728230535.png)

> **Note:** After creation, the VPC contains a default Route Table but no Subnets or Internet Gateway.

---

# Step 2 - Create a Public Subnet

1. Navigate to:

```text
Subnets
    ↓
Create Subnet
```

2. Select the VPC created in Step 1.
3. Enter a subnet name.

> **Tip:** It is common to include the Availability Zone in the subnet name.

Example:

```text
myapp-prod-public-us-east-1
```

4. Select the Availability Zone.
5. Set the IPv4 Subnet CIDR Block:

```text
10.0.0.0/28
```

6. Click **Create Subnet**.

![Pasted image 20260728230545](../../../images/Pasted%20image%2020260728230545.png)

---

# Step 3 - Create an Internet Gateway

1. Navigate to:

```text
Internet Gateways
    ↓
Create Internet Gateway
```

2. Enter a name.
3. Click **Create Internet Gateway**.

![Pasted image 20260728230555](../../../images/Pasted%20image%2020260728230555.png)

---

# Step 4 - Attach Internet Gateway to the VPC

After creating the Internet Gateway:

1. Open the Internet Gateway details page.
2. Click:

```text
Actions
    ↓
Attach to VPC
```

3. Select the VPC created earlier.
4. Click **Attach Internet Gateway**.

![Pasted image 20260728230603](../../../images/Pasted%20image%2020260728230603.png)

> **Important:** Creating an Internet Gateway is **not enough**. It must also be attached to the VPC.

---

# Step 5 - Add an Internet Route

1. Open the VPC.
2. Go to the **Resource Map**.
3. Open the associated **Route Table**.

![Pasted image 20260728230609](../../../images/Pasted%20image%2020260728230609.png)

---

## Edit Routes

1. Click **Edit Routes**.
2. Click **Add Route**.
3. Configure the route as follows:

| Destination | Target |
|-------------|--------|
| `0.0.0.0/0` | Internet Gateway (Select the IGW created earlier) |

4. Click **Save Changes**.

![Pasted image 20260728230617](../../../images/Pasted%20image%2020260728230617.png)

---

# Verify the VPC

After completing the above steps, revisit the VPC.

The Resource Map should show:

- VPC
- Public Subnet

all correctly connected.

# Network ACLs (NACLs)

Navigate to:

```text
VPC Dashboard
    ↓
Network ACLs
```

## List of Network ACLs

The **Network ACLs** page displays:

- Network ACL ID
- Associated Subnets
- Default/Custom NACL
- Associated VPC ID
- Owner ID

![Pasted image 20260728230738](../../../images/Pasted%20image%2020260728230738.png)


---

## Details of a Network ACL

Select a Network ACL to view its details.

Key points:

- Every VPC automatically includes a **default Network ACL**.
- Every subnet must be associated with **one** Network ACL.
- A single Network ACL can be associated with **multiple subnets**.

---

## Inbound & Outbound Rules

The **Inbound Rules** and **Outbound Rules** tabs define the traffic allowed to enter or leave associated subnets.

Key points:

- Default Network ACL allows all IPv4 inbound and outbound traffic.
- Rules are evaluated in ascending order (lowest rule number first).
- Network ACLs are **stateless**, so inbound and outbound traffic must both be explicitly allowed.


---

# Notes

- This setup provides the minimum networking required for an **Elastic Beanstalk (EC2-based)** web application.
- No Private Subnets or NAT Gateway are required because the application consists of a single Internet-facing resource.
- **AWS Lambda** does not require a VPC to be publicly accessible, as it can be invoked through services such as **API Gateway**.
