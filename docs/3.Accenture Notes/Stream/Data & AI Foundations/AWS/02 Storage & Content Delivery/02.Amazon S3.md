# Amazon Simple Storage Service (Amazon S3)

---

# Introduction

**Amazon Simple Storage Service (Amazon S3)** is AWS's **fully managed object storage service** designed to store and retrieve virtually unlimited amounts of data from anywhere in the world.

It is one of the oldest and most widely used AWS services, serving as the backbone for backups, static websites, media storage, analytics, data lakes, disaster recovery, and much more.

Amazon S3 is built for **high durability, scalability, availability, and security**, making it suitable for applications ranging from personal websites to enterprise-scale data platforms.

> [!IMPORTANT]
> **Amazon S3 is an Object Storage Service**, not a file system or a traditional database.

---

# What is Object Storage?

Unlike traditional file systems that organize data into folders and directories, Amazon S3 stores data as **Objects** inside **Buckets**.

Each object consists of:

- The actual file (data)
- Metadata (information about the file)
- A unique object key (identifier)

```text
Bucket
│
├── image.png
├── report.pdf
├── backup.zip
└── video.mp4
```

> [!NOTE]
> A bucket is similar to a top-level container, while objects are the files stored inside it.

# Key Components

## Bucket

A **Bucket** is the container that stores objects.

Characteristics:

- Created in a specific AWS Region
- Bucket names must be **globally unique**
- Can contain virtually unlimited objects

---

## Object

An **Object** is the actual data stored in S3.

Examples:

- Images
- Videos
- PDFs
- ZIP files
- Logs
- Backups

Maximum object size:

```text
5 TB
```

---

## Object Key

Every object has a unique **key** (its name/path) within a bucket.

Example:

```text
images/profile.jpg
documents/report.pdf
```

# S3 Storage Classes

Amazon S3 provides multiple **Storage Classes**, allowing you to balance **cost**, **performance**, and **data access frequency**.

---

## 1. S3 Standard

### Purpose

General-purpose storage for data that is accessed frequently.

### Best For

- Frequently accessed files
- Web applications
- Static websites
- Active business data

### Characteristics

- Low latency
- High throughput
- High availability

---

## 2. S3 Standard-Infrequent Access (Standard-IA)

### Purpose

Lower-cost storage for data that is accessed less frequently but still requires rapid retrieval.

### Best For

- Backups
- Disaster recovery
- Older project files

### Characteristics

- Lower storage cost
- Rapid access when needed

---

## 3. S3 One Zone-Infrequent Access (One Zone-IA)

### Purpose

Stores infrequently accessed data in **a single Availability Zone**.

### Best For

- Re-creatable data
- Secondary backups

### Characteristics

- Lower cost than Standard-IA
- Data stored in only one AZ

> [!WARNING]
> Since data is stored in only one Availability Zone, it provides lower resilience than multi-AZ storage classes.

---

## 4. S3 Intelligent-Tiering

### Purpose

Automatically moves objects between storage tiers based on access patterns.

### Best For

- Data with unpredictable access frequency
- Long-term datasets

### Characteristics

- Automatic optimization
- Reduces storage costs
- No need to manually change storage classes

---

## 5. S3 Glacier Instant Retrieval

### Purpose

Low-cost archival storage with **millisecond retrieval times**.

### Best For

- Archive data that still requires immediate access

---

## 6. S3 Glacier Flexible Retrieval

### Purpose

Archive storage with multiple retrieval speed options.

Retrieval options include:

- Expedited
- Standard
- Bulk

### Best For

- Archive storage where retrieval time can vary

---

## 7. S3 Glacier Deep Archive

### Purpose

The **lowest-cost storage class** for long-term archival.

### Best For

- Compliance records
- Long-term backups
- Historical archives

### Characteristics

- Lowest storage cost
- Designed for data rarely accessed

---

# Storage Class Comparison

| Storage Class | Access Frequency | Retrieval Speed | Typical Use Case |
|---------------|-----------------|----------------|------------------|
| S3 Standard | Frequent | Immediate | Active application data |
| Standard-IA | Infrequent | Rapid | Backups |
| One Zone-IA | Infrequent | Rapid | Re-creatable backups |
| Intelligent-Tiering | Unknown | Automatic | Variable workloads |
| Glacier Instant Retrieval | Rare | Milliseconds | Archived data needing quick access |
| Glacier Flexible Retrieval | Rare | Configurable | Archive storage |
| Glacier Deep Archive | Very Rare | Slowest | Long-term archival & compliance |

# Durability vs Availability

## Durability

Durability measures the likelihood that your data remains intact over time.

Amazon S3 provides:

```text
99.999999999%
(11 Nines)
```

This means your objects are extremely unlikely to be lost.

---

## Availability

Availability measures how often the service is accessible when requested.

For **S3 Standard**, AWS provides approximately:

```text
99.99%
```

annual availability.

> [!NOTE]
> Durability protects your data from loss, while availability ensures you can access it when needed.

---

# Multipart Upload

Large files should be uploaded using **Multipart Upload**.

Recommended for:

```text
Files larger than ~100 MB
```

Required for some SDK upload methods.

Benefits:

- Faster uploads
- Improved reliability
- Resume interrupted uploads

---

# Amazon S3 Transfer Acceleration

**S3 Transfer Acceleration** speeds up uploads and downloads over long distances.

Instead of sending data directly to the S3 Region, uploads first reach the nearest AWS **Edge Location**, then travel through the AWS global network.

```text
User
   │
   ▼
Nearest AWS Edge Location
   │
AWS Global Network
   │
   ▼
Amazon S3 Bucket
```

### Best For

- Global users
- Large file uploads
- High-latency networks

# Common Use Cases

Amazon S3 is commonly used for:

- Static website hosting
- Content distribution (with CloudFront)
- File storage
- Backup and Restore
- Disaster Recovery
- Log Archiving
- Data Lakes
- Analytics
- Long-term archival storage

---

# Best Practices

- Choose the appropriate Storage Class based on access patterns.
- Use **Intelligent-Tiering** if access frequency is unpredictable.
- Use **Multipart Upload** for large files.
- Enable **Transfer Acceleration** for globally distributed users when upload performance is important.
- Remember that bucket names must be globally unique.
