# Lab: Create and Query a DynamoDB Table

## Objective

Learn how to create a DynamoDB table, insert items, query data efficiently, explore table features, and clean up resources.

---

# Step 1 - Open the DynamoDB Dashboard

1. Sign in to the **AWS Management Console**.
2. Navigate to **Amazon DynamoDB**.
3. From the dashboard, click **Create table**.

# Step 2 - Create a DynamoDB Table

Create the following table:

| Setting | Value |
|---------|-------|
| Table Name | `ArtistSongs` |
| Partition Key | `ArtistId` |
| Sort Key | `SongTitle` |

![[../../../../../../../Pasted image 20260801212902.png]]

> [!NOTE]
> DynamoDB tables should be designed around **how your application queries data**, rather than around entities like relational databases.

### Table Design

The table is intended to answer questions like:

> **"Show me all songs by a particular artist."**

Example structure:

| ArtistId | SongTitle | Artist |
|----------|-----------|--------|
| 1 | Believer | Imagine Dragons |
| 1 | Demons | Imagine Dragons |
| 2 | Shape of You | Ed Sheeran |

---

# AWS CLI - Create Table

```bash
aws dynamodb create-table \
--table-name MyTableName \
--attribute-definitions AttributeName=MyPrimaryKey,AttributeType=S \
--key-schema AttributeName=MyPrimaryKey,KeyType=HASH \
--provisioned-throughput ReadCapacityUnits=5,WriteCapacityUnits=5
```

# Step 4 - Query Data

DynamoDB provides two methods for retrieving data:

## Query (Recommended)

A **Query** searches using the **Partition Key** (and optionally the Sort Key).

Advantages:

- Fast
- Efficient
- Cost-effective
- Reads only the required partitions

Example:

Retrieve all songs for:

```text
ArtistId = 1
```

Steps:

1. Open **Explore Items**.
2. Switch to **Query** mode.
3. Enter:

```text
Partition Key = 1
```

4. Click **Run**.

![[../../../../../../../Pasted image 20260801213217.png]]

---

## Scan

A **Scan** reads **every item** in the table.

Use only when:

- Searching the entire table
- Working with very small datasets
- Running reports

> [!WARNING]
> Scan operations become slower and more expensive as tables grow larger.

---

## Query vs Scan

| Query | Scan |
|--------|------|
| Reads selected partitions | Reads the entire table |
| Faster | Slower |
| Lower cost | Higher cost |
| Uses keys | Does not require keys |
| Recommended | Use only when necessary |

> [!TIP]
> Design DynamoDB tables around predictable **Query** patterns instead of relying on **Scan** operations.

# Explore Table Features

## 1. Overview

Displays general information such as:

- Table Name
- Partition Key
- Sort Key
- Region
- ARN
- Encryption Status
 

---

## 2. Indexes

Indexes improve query performance by providing alternative ways to retrieve data.

Use indexes when applications need additional query patterns beyond the primary key.

 
---

## 3. Metrics

Monitor table performance including:

- Read Capacity
- Write Capacity
- Read Requests
- Write Requests
- Throttled Requests

 

---

## 4. Global Tables

Global Tables automatically replicate DynamoDB tables across multiple AWS Regions.

Benefits:

- Multi-region availability
- Disaster recovery
- Lower latency for global users
 

---

## 5. Backups

DynamoDB supports continuous backups with **Point-in-Time Recovery (PITR)**.

Features:

- Restore table to an earlier state
- Continuous backups for up to **35 days**
 

---

## 6. Read/Write Capacity

Configure how much throughput is allocated to the table for reading and writing data.
 

---

# AWS Best Practice

> [!IMPORTANT]
> Design DynamoDB tables based on **application access patterns**, not database entities.

Ask:

> **"How will the application retrieve data?"**

before designing the table.
