# Lab: Create an Amazon RDS (MySQL) Database

## Objective

In this lab, you will learn how to:

- Prepare a VPC for Amazon RDS
- Create an additional subnet in another Availability Zone
- Create a MySQL RDS database
- Explore the RDS Dashboard
- View database details and monitoring information
- Delete the database after use

> [!IMPORTANT]
> **Amazon RDS requires a VPC with at least two subnets in two different Availability Zones (AZs)** to support high availability and failover capabilities.

---

# Prerequisite

Before creating an RDS database, ensure you already have:

- A VPC
- One subnet created inside the VPC

If you completed the previous VPC lab, you'll simply create **one additional subnet** in a different Availability Zone.

# Step 1 - Create a Second Subnet

## A. Check Existing VPC

1. Open the **AWS Management Console**
2. Navigate to:

```text
VPC
    ↓
Your VPCs
```

3. Select your existing VPC.
4. Open the **Resource Map** tab.
5. Note the **Availability Zone (AZ)** of the existing subnet.
 

> [!NOTE]
> The new subnet **must** be created in a **different Availability Zone** from the existing subnet.

---

## B. Create a New Subnet

Navigate to:

```text
VPC
    ↓
Subnets
```

Click **Create Subnet**.

Configure the subnet:

| Setting | Value |
|---------|-------|
| VPC | Your existing VPC |
| Name | Any meaningful name (e.g., `my-vpc-us-east-1b`) |
| Availability Zone | Different from the existing subnet |
| IPv4 CIDR Block | `10.0.0.16/28` |

### Why `10.0.0.16/28`?

Previously, the first subnet used:

```text
10.0.0.0/28
```

A `/28` subnet contains:

```text
16 IP Addresses
```

Therefore:

First subnet:

```text
10.0.0.0
to
10.0.0.15
```

The next available subnet begins at:

```text
10.0.0.16
```

Hence:

```text
10.0.0.16/28
```

> [!TIP]
> AWS provides a **Next CIDR Block (>)** button that automatically calculates the next available subnet range.

# AWS CLI - Create an RDS Instance

```bash
aws rds create-db-instance \
--db-instance-identifier <database-name> \
--db-instance-class db.t3.micro \
--engine mysql \
--master-username <username> \
--master-user-password <password> \
--allocated-storage <storage-size>
```

# Monitoring

The Monitoring tab displays database performance metrics such as:

- CPU Utilization
- Active Connections
- Free Storage
- Read/Write Activity
- Memory Usage
 
These metrics help monitor database health and troubleshoot performance issues.

---

# Logs & Events

Displays important database events including:

- Database creation
- Backups
- Maintenance activities
- Failures
- Restarts
 

---

# Configuration

Displays configuration details such as:

- Database ARN
- Engine Version
- Master Username
- Database Identifier
- Storage Allocation
- Instance Type
- Creation Time

# Maintenance & Backups

Amazon RDS automatically creates backups and snapshots.

Here you can:

- View automatic backups
- Configure backup retention
- Restore databases
- View maintenance schedules
