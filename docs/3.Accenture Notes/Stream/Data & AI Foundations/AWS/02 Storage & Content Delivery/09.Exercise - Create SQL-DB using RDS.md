# Lab: Create and Connect to an Amazon RDS MySQL Database

## Objective

In this lab, you will learn how to:

- Create a MySQL database using Amazon RDS
- Review the database instance configuration
- Connect to the database using MySQL Workbench
- Understand common connection issues
- Delete the database to avoid AWS charges

---

# Prerequisites

Before starting, ensure you have:

- An AWS account
- A VPC (default or custom)
- MySQL Workbench installed (for Step 3)

---

# Step 1 - Create a MySQL Database

Navigate to:

```text
AWS Console
    ↓
Amazon RDS
    ↓
Databases
    ↓
Create Database
```

📷 **Image Placeholder – RDS Dashboard**

---

## Database Configuration

### Database Creation Method

Select:

```text
Standard Create
```

---

### Engine Options

| Setting | Value |
|---------|-------|
| Engine Type | MySQL |
| Edition | MySQL Community |
| Version | Default |

---

### Template

Choose:

```text
Free Tier
```

This is suitable for:

- Learning
- Development
- Testing

---

### Database Settings

| Setting | Value |
|---------|-------|
| DB Instance Identifier | Your choice |
| Master Username | Your choice |
| Master Password | Your choice |

> Save your **Master Username** and **Password**. They are required when connecting to the database later.

| Setting | Value |

| Storage Autoscaling | Disabled |

| Setting | Value |
|---------|-------|

# Step 2 - View Database Details

Once the database has been created:

Navigate to:

```text
Amazon RDS
    ↓
Databases
```

Wait until the database status becomes:

```text
Available
```
 

Click the **DB Identifier** to open the database details.

Review the configuration, including:

- Database Engine
- Storage
- CPU
- Networking
- Security
- Monitoring

Scroll through the page to become familiar with the available settings.

---

## Install MySQL Workbench

Download and install **MySQL Workbench** if it is not already installed.

---

# Troubleshooting Connection Issues

If the connection fails:

## Check the Security Group

Ensure the RDS Security Group allows inbound MySQL traffic.

Navigate to:

```text
Amazon RDS
    ↓
Database
    ↓
Connectivity & Security
    ↓
Security Group
```

Verify an inbound rule exists for:

| Type | Port | Source |
|------|------|--------|
| MySQL/Aurora | 3306 | Your IP address (recommended) or Anywhere (0.0.0.0/0) for lab purposes |

![Pasted image 20260801214825](../../../images/Pasted%20image%2020260801214825.png)
![Pasted image 20260801214840](../../../images/Pasted%20image%2020260801214840.png)

> [!WARNING]
> Allowing access from **Anywhere (0.0.0.0/0)** is acceptable only for learning or testing. In production, always restrict access to trusted IP addresses.

# Step 4 - Delete the Database

To prevent unnecessary AWS charges:

Navigate to:

```text
Amazon RDS
    ↓
Databases
```

Select your database.

Click:

```text
Actions
    ↓
Delete
```

---

## Delete Options

Before confirming deletion:

Uncheck:

- Create Final Snapshot
- Retain Automated Backups

Type:

```text
delete me
```

Click:

```text
Delete
```
 

---

## Verify Cleanup

After deletion, verify that:

- No RDS instance remains.
- No final snapshots exist.
- No retained automated backups exist.

This ensures there are no remaining resources that could incur charges.
