# Amazon CloudFront

---

# Introduction

**Amazon CloudFront** is AWS's **Content Delivery Network (CDN)** service that delivers web content to users with **low latency**, **high transfer speeds**, and **high availability**.

Instead of serving every request directly from your application's server, CloudFront caches copies of your content in **Edge Locations** distributed around the world. When users request your website or files, CloudFront serves them from the **nearest edge location**, reducing the distance the data must travel.

> [!IMPORTANT]
> **Amazon CloudFront is a global Content Delivery Network (CDN) that speeds up content delivery by caching content at AWS Edge Locations close to users.**

---

# Why Use a CDN?

Imagine your web server is located in **Ohio (USA)**.

If a user accesses your website from:

- India
- Australia
- Germany

their request must travel thousands of kilometers to reach your server, increasing latency.

Without a CDN:

```text
User (India)
      │
      ▼
Web Server (USA)
```

Every request travels across continents.

---

With CloudFront:

```text
                Origin Server (USA)
                        │
        ┌───────────────┼───────────────┐
        │               │               │
        ▼               ▼               ▼
 Edge Location     Edge Location    Edge Location
   (India)            (Europe)          (Japan)
        ▲
        │
     User
```

The first request retrieves content from the origin server.

Future requests are served directly from the nearest Edge Location.

Result:

- Lower latency
- Faster loading
- Better user experience

---

# How CloudFront Works

## Step 1

A user requests a website or file.

```text
www.example.com/image.jpg
```

---

## Step 2

CloudFront checks the nearest **Edge Location**.

If the file already exists in the cache:

```text
Edge Location
      │
      ▼
User
```

The file is delivered immediately.

This is called a **Cache Hit**.

---

## Step 3

If the file is **not cached**, CloudFront retrieves it from the **Origin Server**.

```text
User
      │
      ▼
Edge Location
      │
      ▼
Origin Server
```

The file is:

1. Downloaded from the origin.
2. Stored in the edge cache.
3. Delivered to the user.

This is called a **Cache Miss**.

---

## Step 4

Future requests are served directly from the cached copy.

```text
User
      │
      ▼
Nearest Edge Location
```

No communication with the origin server is required until the cache expires.

# Origin

The **Origin** is the original location where CloudFront retrieves content.

CloudFront supports multiple origin types.

---

## Supported AWS Origins

### Amazon S3

Used for:

- Images
- Videos
- Static websites
- Downloads

---

### Amazon EC2

Used for:

- Dynamic websites
- APIs
- Web applications

---

### Elastic Load Balancer (ELB)

Distributes requests across multiple EC2 instances.

CloudFront can use the load balancer as the origin.

---

### Lambda@Edge

Runs serverless code at Edge Locations before serving content.

Common uses:

- Authentication
- URL rewriting
- Header modification
- Personalization

---

### AWS Shield

Provides DDoS protection for applications delivered through CloudFront.

---

## Non-AWS Origins

CloudFront is **not limited to AWS**.

It can also retrieve content from:

- On-premises web servers
- Third-party hosting providers
- External HTTP/HTTPS servers

---

# Edge Locations

An **Edge Location** is a small AWS data center distributed worldwide.

Purpose:

- Cache frequently requested content
- Reduce latency
- Deliver content quickly

AWS continuously expands the number of Edge Locations worldwide.

> [!NOTE]
> Edge Locations are different from AWS Regions. They are specifically optimized for fast content delivery.

---

# Caching

CloudFront temporarily stores copies of files in Edge Locations.

Cached content may include:

- Images
- CSS files
- JavaScript
- HTML
- Videos
- PDFs

Benefits:

- Faster responses
- Reduced origin server load
- Lower bandwidth usage

---

# Cache Hit vs Cache Miss

## Cache Hit

```text
User
      │
      ▼
Edge Location
```

The requested content already exists in cache.

Advantages:

- Fastest response
- No request sent to origin
- Lowest latency

---

## Cache Miss

```text
User
      │
      ▼
Edge Location
      │
      ▼
Origin Server
```

The content is not cached.

CloudFront:

- Retrieves it from the origin
- Stores it in cache
- Returns it to the user

---

# Cache Control Headers

CloudFront determines how long objects remain cached using **Cache-Control headers**.

These headers tell CloudFront:

- How long to cache a file
- When to check for updates
- When to refresh cached content

Developers can also manually:

- Invalidate cached objects
- Remove outdated content
- Force CloudFront to fetch updated files

# Geo Restriction (Geo Blocking)

CloudFront supports **GeoIP-based restrictions**.

You can:

- Allow content only in selected countries
- Block access from specific countries

Example:

```text
Allow:
India
USA

Block:
Country X
Country Y
```

Common use cases:

- Licensing restrictions
- Regional content
- Compliance requirements

```text
User Requests Content
          │
          ▼
Nearest Edge Location
          │
     Cached?
      │        │
     Yes       No
      │        │
      ▼        ▼
 Serve      Fetch From
 Content   Origin Server
                │
```

# Best Practices

- Use CloudFront for globally accessed websites.
- Store static content in Amazon S3 and deliver it through CloudFront.
- Configure cache headers appropriately.
- Use Geo Restrictions when regional access must be controlled.
- Invalidate cached content after major website updates.

# Interview One-Liners

**Amazon CloudFront**  
> Amazon CloudFront is AWS's global Content Delivery Network (CDN) that delivers content with low latency by caching data at Edge Locations close to users.

**Edge Location**  
> An Edge Location is a geographically distributed AWS data center that caches and serves content closer to end users.

**Origin**  
> The origin is the original source of content that CloudFront retrieves when the requested object is not available in cache.

**Cache Hit**  
> A cache hit occurs when the requested content is already available at the nearest Edge Location and can be served immediately.

**Cache Miss**  
> A cache miss occurs when the requested content is not cached, causing CloudFront to fetch it from the origin before serving the user.
