# Amazon CloudFront + Amazon S3 Integration Lab

> [!INFO]
> **Goal:** Learn how to securely deliver content stored in a private Amazon S3 bucket using Amazon CloudFront.

**Objectives**

- Understand S3 Public Access settings.
- Learn how Bucket Policies control access.
- Create a CloudFront Distribution.
- Configure Origin Access Control (OAC).
- Serve private S3 content securely through CloudFront.
- Clean up all AWS resources.

---

# Part 1 — Understanding S3 Public Access & Bucket Policies

One of the most common beginner mistakes is making an S3 bucket public when it doesn't need to be.

AWS provides two mechanisms that work together:

- **Block Public Access** (account/bucket level protection)
- **Bucket Policy** (permission rules)

Understanding how these interact is extremely important.

---

# Scenario A — Public S3 Bucket

## Step 1 — Create a Public Bucket

Follow the **Create S3 Bucket** lab.

During bucket creation:

- Disable **Block all public access**
- Leave the bucket public
- Do **not** delete the bucket after creation

---

## Step 2 — Add a Bucket Policy

Navigate to:

```text
S3
→ Bucket
→ Permissions
→ Bucket Policy
→ Edit
```

Paste the following policy (replace the bucket name):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/*"
    }
  ]
}
```

### What does this policy do?

| Field | Meaning |
|--------|----------|
| Effect | Allow access |
| Principal | Anyone (`*`) |
| Action | Read objects (`GetObject`) |
| Resource | Every object inside the bucket |
![[../../../../../../../Pasted image 20260801215322.png]]
This makes every object publicly readable.

---

## Step 3 — Verify Public Access

Navigate to:

```text
Bucket
→ Objects
```

Select:

```text
sample.html
```

Click:

```text
Copy URL
```

Paste the URL into a browser.
![[../../../../../../../Pasted image 20260801215345.png]]

Expected result:
![[../../../../../../../Pasted image 20260801215354.png]]
The HTML page opens successfully.

> **Why?**  
> The bucket is public, and the bucket policy explicitly allows everyone to read objects.

# Scenario B — Private S3 Bucket

Now convert the same bucket into a private bucket.

---

## Step 1 — Enable Block Public Access

Navigate to:

```text
Bucket
→ Permissions
```

Enable:

```text
Block all public access
```

Save changes.

---

## Step 2 — Remove Bucket Policy

Still under:

```text
Permissions
```

Delete the existing bucket policy.

Save changes.
![[../../../../../../../Pasted image 20260801215429.png]]

---

## Step 3 — Try Adding the Policy Again

Attempt to paste the same public bucket policy.

AWS displays an error similar to:

```text
Your bucket policy changes can't be saved.
```
![[../../../../../../../Pasted image 20260801215439.png]]
### Why?

Because **Block Public Access** overrides attempts to expose the bucket publicly.

AWS prevents accidental exposure of data.

---

## Step 4 — Verify Access

Copy the object URL again.

Open it in a browser.

Force refresh:

**Windows**

```text
CTRL + SHIFT + R
```

**macOS**

```text
CMD + SHIFT + R
```

Expected result:

```text
Access Denied
```
![[../../../../../../../Pasted image 20260801215453.png]]

The object still exists, but anonymous users are no longer allowed to access it.

---

# Summary — Public vs Private Bucket

| Setting | Result |
|----------|--------|
| Block Public Access OFF | Bucket policies can grant public access |
| Block Public Access ON | Public bucket policies cannot be applied |
| Public bucket | Files accessible directly via S3 URL |
| Private bucket | Files return **Access Denied** |

> [!IMPORTANT]
> **Block Public Access** does **not** automatically delete an existing bucket policy. It simply prevents public access from being granted while it is enabled.

# Part 2 — Create a CloudFront Distribution

Now we'll keep the bucket **private** while still allowing users to access its contents securely through CloudFront.

# Step 6 — Update the Bucket Policy

After deployment, AWS displays a banner:

```text

```

Click:

```text

```

```text
S3
→ Bucket
→ Permissions
```

Paste the copied JSON.

> [!TIP]
> Unlike the earlier public bucket policy, this policy **does not** allow everyone (`*`) to access the bucket. Instead, it grants access **only to the CloudFront distribution**.

# How It Works

```text
User
   │
   ▼
CloudFront URL
   │
   ▼
CloudFront Edge Location
   │
   ▼
Private S3 Bucket
```

Users never access S3 directly.

CloudFront acts as the trusted intermediary.

---

# Why This Is More Secure

Instead of exposing the bucket publicly:

```text
Internet
     │
     ▼
Public S3 Bucket
```

You expose only CloudFront:

```text
Internet
     │
     ▼
CloudFront
     │
     ▼
Private S3 Bucket
```

Benefits:

- S3 remains private
- Better security
- Global caching
- Faster performance

---

# Caching Behavior

Once CloudFront retrieves an object:

```text
sample.html
```

it caches the file at AWS Edge Locations.

Subsequent users receive the file directly from the nearest Edge Location instead of S3.

This reduces:

- Latency
- S3 requests
- Network traffic

> [!NOTE]
> It may take a few minutes after deployment for CloudFront to fetch and cache the content.

## Delete CloudFront Distribution

Navigate to:

```text
CloudFront
→ Distributions
```

1. Select the distribution.
2. Click **Disable**.
3. Wait until the status changes to **Disabled**.
4. Select it again.
5. Click **Delete**.

Navigate to:

```text
CloudFront
→ Origin Access
```

Delete the associated Origin Access Control if one was created.

---

Navigate to:

```text
S3
→ Bucket
```

Before deleting:

1. Empty the bucket.
2. Delete all objects.
3. Delete the bucket.

```text
                     Private Amazon S3 Bucket
```

# Key Takeaways

> [!SUCCESS]
> **Block Public Access** protects S3 buckets from accidental public exposure.
>**Bucket Policies** define who or what can access bucket objects.
> A **public bucket** allows direct object access through S3 URLs.
> A **private bucket** returns **Access Denied** unless an authorized service accesses it.
> **CloudFront + Origin Access Control (OAC)** enables secure delivery of private S3 content.
> CloudFront caches objects at **Edge Locations**, improving performance while keeping the origin bucket private.
