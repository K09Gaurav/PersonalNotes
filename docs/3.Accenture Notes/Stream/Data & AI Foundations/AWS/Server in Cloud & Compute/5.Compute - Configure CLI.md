# AWS CLI Installation and Configuration

---

# Introduction

The **AWS Command Line Interface (AWS CLI)** allows you to interact with AWS services directly from your terminal or command prompt.

Instead of using the AWS Management Console (GUI), you can execute commands to:

- Create resources
- Configure services
- Update infrastructure
- Delete resources
- Automate deployments

The AWS CLI is one of the most important tools used by Cloud Engineers, DevOps Engineers, and System Administrators because it enables scripting and automation.

> [!IMPORTANT]
> Before you can use the AWS CLI, you must:
>
> 1. Install AWS CLI
> 2. Create an IAM User (or obtain credentials)
> 3. Configure the AWS CLI with your credentials

# Step 1 – Install AWS CLI

## What is AWS CLI?

AWS CLI is a command-line tool that communicates with AWS services using AWS APIs.

It is available for:

- Windows
- Linux
- macOS

AWS recommends installing **AWS CLI Version 2 (v2)**.

---

## Verify Installation

After installation, verify that AWS CLI is installed correctly.

### Linux/macOS

```bash

```

Displays the installation path.

Example:

```text
/usr/local/bin/aws
```

---

### Check Version

```bash
aws --version
```

Example Output

```text
aws-cli/2.x.x Python/3.x.x Linux
```

If a version number is displayed, the installation was successful.

# Step 2 – Create an IAM User

## Why Create an IAM User?

AWS strongly recommends **not using the Root Account** for daily work.

Instead, create an **IAM User** with the required permissions.

The AWS CLI authenticates using this IAM User's credentials.

> [!IMPORTANT]
> Never use the AWS Root Account for everyday CLI operations.

---

## AWS IAM

**AWS Identity and Access Management (IAM)** is the AWS service responsible for:

- Authentication
- Authorization
- User Management
- Permissions

IAM controls who can access AWS resources and what actions they can perform.

---

# What is an Access Key?

An AWS **Access Key** consists of two parts.

---

## Access Key ID

Public identifier used to identify the IAM User.

Example

```text
AKIAIOSFODNN7EXAMPLE
```

---

## Secret Access Key

Private credential used to authenticate requests.

Example

```text
wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
```

Never share your Secret Access Key.

---

# Classroom Temporary Credentials

Some training environments (such as Udacity labs) generate **temporary AWS credentials**.

These consist of:

- Access Key ID
- Secret Access Key
- Session Token

Unlike permanent IAM credentials, temporary credentials expire after a few hours.

---

# Step 3 – Configure AWS CLI

Once you have credentials, configure the AWS CLI.

Run:

```bash
aws configure
```

The CLI prompts for four values.

---

## 1. AWS Access Key ID

Paste the generated Access Key ID.

Example

```text
AKIAIOSFODNN7EXAMPLE
```

---

## 2. AWS Secret Access Key

Paste the Secret Access Key.

---

## 3. Default Region

Specify the AWS Region where commands should execute by default.

Example

```text
us-east-1
```

or

```text
ap-south-1
```

Choose the region assigned to your AWS account or training environment.

> [!IMPORTANT]
> The default region is **not always us-east-1**. Use the region associated with your AWS account.

---

## 4. Default Output Format

Choose how AWS CLI displays responses.

Supported formats:

- json
- yaml
- text
- table

Example

```text
json
```

JSON is the most commonly used format.

# AWS CLI Configuration Files

AWS stores configuration in two hidden files.

---

## Credentials File

Stores authentication credentials.

Location

```text
~/.aws/credentials
```

Contains:

- Access Key ID
- Secret Access Key

---

## Config File

Stores profile configuration.

Location

```text
~/.aws/config
```

Contains:

- Region
- Output format
- Profile settings

---

# AWS Profiles

A **Profile** is a named collection of AWS CLI settings.

By default:

```text
default
```

You can create multiple profiles.

Example

```bash
aws configure --profile dev
```

or

```bash
aws configure --profile production
```

Use profiles when managing multiple AWS accounts.

---

# Temporary Session Token

Training environments often provide temporary credentials.

In that case, configure the session token.

```bash
aws configure set aws_session_token "YOUR_SESSION_TOKEN"
```

This step is **only required for temporary credentials**.

Permanent IAM Users do **not** require a session token.

# Using Multiple Profiles

If multiple profiles exist:

```bash
aws iam list-users --profile dev
```

The `--profile` option tells the CLI which profile to use.

---

# Updating Configuration

You do not need to rerun `aws configure` every time.

Individual settings can be updated.

Example

Update Region

```bash
aws configure set default.region us-east-1
```

This changes only the region while keeping the remaining configuration unchanged.

---

# Environment Variables

AWS CLI can also obtain credentials from environment variables.

Examples:

Linux/macOS

```bash
export AWS_CONFIG_FILE=~/.aws/config

export AWS_SHARED_CREDENTIALS_FILE=~/.aws/credentials
```

Windows (Git Bash)

```bash
setx AWS_ACCESS_KEY_ID AKIA...

setx AWS_SECRET_ACCESS_KEY ********

setx AWS_DEFAULT_REGION us-east-1
```

Environment variables are commonly used in:

- CI/CD Pipelines
- Jenkins
- GitHub Actions
- Docker Containers

# Security Best Practices

- Never share your Secret Access Key.
- Never upload credentials to GitHub.
- Use IAM Users instead of the Root Account.
- Enable Multi-Factor Authentication (MFA).
- Rotate Access Keys regularly.
- Use the Principle of Least Privilege.
- Prefer IAM Roles for applications instead of long-term credentials.

# Important Notes

> [!WARNING]

>
> In production environments, always grant users only the permissions they require.

---

> [!WARNING]

>
> If AWS commands suddenly fail with permission errors, refresh the classroom and generate new credentials.

# Memory Trick

> [!TIP]
> Think of the AWS CLI like logging into an online banking app:
>
> - **IAM User** → Your username
> - **Access Key ID** → Your account number
> - **Secret Access Key** → Your password
> - **Session Token** → A temporary OTP (used only for temporary credentials)
> - **Region** → The branch where your requests are sent
>
> Without valid credentials, AWS will reject every request.

# Interview One-Liners

**AWS CLI**
> A command-line tool that enables users to manage AWS services programmatically using terminal commands.

**IAM User**
> An AWS identity with specific permissions used to securely access AWS resources.

**Access Key ID**
> The public portion of AWS programmatic credentials used to identify an IAM user.

**Secret Access Key**
> The private credential used with the Access Key ID to authenticate AWS CLI requests.

**AWS Profile**
> A named collection of AWS CLI configuration settings, including credentials, region, and output format.

**Default Region**
> The AWS Region where CLI commands are executed unless another region is explicitly specified.

**Session Token**
> A temporary credential required when using temporary AWS security credentials, such as those provided by AWS STS or classroom environments.
