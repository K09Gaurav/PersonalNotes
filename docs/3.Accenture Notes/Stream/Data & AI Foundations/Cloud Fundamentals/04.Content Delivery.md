# Introduction

When users access a website or web application, they expect pages, images, videos, and other resources to load almost instantly. However, if the web server is located far from the user, it can take longer for the requested content to travel across the Internet.

To solve this problem, cloud providers use a **Content Delivery Network (CDN)**.

A **Content Delivery Network (CDN)** improves website performance by storing copies of frequently accessed content at locations closer to users, reducing the time it takes to deliver that content.

---

# What is a Content Delivery Network (CDN)?

## Definition

A **Content Delivery Network (CDN)** is a globally distributed network of servers that stores (**caches**) copies of website content at locations closer to end users.

Instead of every request traveling to the original web server (called the **Origin Server**), users receive content from the nearest CDN location whenever possible.

This significantly improves website performance.

> [!IMPORTANT]
> A CDN **does not replace your original server**. It stores temporary copies (cached content) to speed up content delivery.

---

# How a CDN Works

## Step 1: User Requests Content

A user opens a website or requests a file such as:

- HTML page
- CSS file
- JavaScript
- Image
- Video
- PDF

---

## Step 2: Request Goes to the Nearest Edge Location

Instead of immediately contacting the origin server, the request is routed to the **nearest Edge Location**.

The CDN checks whether the requested content is already stored in its cache.

---

## Step 3A: Cache Hit

If the content **already exists** in the Edge Location:

- The content is delivered immediately.
- The origin server is **not contacted**.
- The user experiences much faster loading times.

This is called a **Cache Hit**.

---

## Step 3B: Cache Miss

If the content **is not available** in the Edge Location:

1. The CDN forwards the request to the **Origin Server**.
2. The origin server sends the requested content.
3. The CDN stores (caches) a copy of the content in the Edge Location.
4. The content is delivered to the user.

Future requests for the same content can now be served directly from the Edge Location.

This is called a **Cache Miss**.

---

# CDN Request Flow

```text
              User
                │
                ▼
        Nearest Edge Location
                │
        ┌───────┴────────┐
        │                │
 Cache Hit          Cache Miss
        │                │
        ▼                ▼
Deliver Content     Origin Server
        │                │
        │         Returns Content
        │                │
        └────────► Cache Content
                         │
                         ▼
                 Deliver to User
```

# What is Caching?

## Definition

**Caching** is the process of storing frequently accessed data temporarily so it can be retrieved much faster during future requests.

Instead of generating or downloading the same content repeatedly, the cached copy is used.

### Examples of Cached Content

- Images
- Videos
- JavaScript files
- CSS files
- Fonts
- HTML pages
- Documents

> [!NOTE]
> Cached content is stored only for a specified amount of time before it is refreshed or removed.

---

# What is an Edge Location?

## Definition

An **Edge Location** is a geographically distributed data center used by a CDN to cache and deliver content closer to users.

Edge Locations are positioned worldwide to reduce the physical distance between users and website content.

### Benefits

- Faster content delivery
- Reduced latency
- Lower bandwidth usage
- Improved reliability

---

# What is an Origin Server?

## Definition

The **Origin Server** is the original source of the website or application content.

It may be:

- A web server
- An application server
- Cloud storage (e.g., Amazon S3)
- A load balancer
- Another backend service

If the requested content is not available in the CDN cache, it is retrieved from the Origin Server.

---

# What is Latency?

## Definition

**Latency** is the time taken for a request to travel from the user to the server and for the response to return.

It is commonly measured in **milliseconds (ms)**.

> [!IMPORTANT]
> **Lower latency = Faster website loading**
>
> **Higher latency = Slower website loading**

### Example

A user in India accessing a server located in the United States will experience higher latency than accessing a nearby server in Mumbai.

By serving content from a nearby Edge Location, a CDN significantly reduces latency.

---

# Benefits of a CDN

## 1. Low Latency

Because content is served from the nearest Edge Location, the distance data travels is reduced.

Benefits include:

- Faster page loading
- Reduced response time
- Improved website performance

---

## 2. Reduced Server Load

Without a CDN:

- Every user request reaches the Origin Server.

With a CDN:

- Most requests are handled by Edge Locations.

This reduces:

- CPU usage
- Memory usage
- Network bandwidth
- Overall workload on the Origin Server

---

## 3. Better User Experience

Fast-loading websites improve:

- Customer satisfaction
- User engagement
- Conversion rates
- Search engine rankings (SEO)

Users are less likely to abandon slow websites.

---

## Additional Benefits

Although not explicitly mentioned in the source material, modern CDNs also commonly provide:

- Improved availability
- Better scalability
- DDoS protection
- Global content delivery
- Lower bandwidth costs

# Amazon CloudFront
#aws

## Definition

**Amazon CloudFront** is AWS's **Content Delivery Network (CDN)** service.

It delivers both **static** and **dynamic** web content through AWS's worldwide network of **Edge Locations**.

CloudFront automatically caches content closer to users, reducing latency and improving website performance.

---

# How Amazon CloudFront Works

## Step 1

A user requests website content.

↓

## Step 2

CloudFront checks the nearest **Edge Location**.

↓

### If Cached (Cache Hit)

- Content is delivered immediately.
- Very fast response.

↓

### If Not Cached (Cache Miss)

- CloudFront contacts the **Origin Server**.
- Retrieves the requested content.
- Stores a copy in the Edge Location.
- Delivers the content to the user.

↓

## Future Requests

Subsequent users requesting the same content receive it directly from the Edge Location.

---

# CloudFront Workflow

```text
        User
          │
          ▼
   CloudFront Edge Location
          │
   ┌──────┴────────┐
   │               │
Cached?          Not Cached
   │               │
Yes ▼             ▼ No
Serve         Origin Server
Content            │
                   ▼
            Retrieve Content
                   │
                   ▼
        Store in Edge Location
                   │
                   ▼
           Deliver to User
```

# Cache Expiration

Cached content does not remain stored forever.

CloudFront allows administrators to configure:

- **Cache Duration (TTL - Time To Live):** How long content remains cached before being refreshed automatically.
- **Manual Cache Invalidation:** Administrators can manually remove or expire cached content when updates are made.

### Why Invalidate the Cache?

Suppose you update your company logo.

Without cache invalidation, users may continue seeing the old logo until the cache expires.

By invalidating the cache, CloudFront retrieves the updated content from the Origin Server immediately.

# CDN vs Origin Server

| CDN (Edge Location) | Origin Server |
|----------------------|---------------|
| Stores cached copies | Stores original content |
| Located near users | May be far from users |
| Faster response | Slower due to distance |
| Handles most requests | Handles cache misses |
| Reduces server workload | Performs primary content generation |

# Real-World Example

Imagine a website hosted in **London**.

### Without a CDN

A user in **India** requests an image.

The request travels all the way to London, increasing latency.

---

### With a CDN

The image has already been cached in a nearby AWS Edge Location in India.

The user receives the image from the local Edge Location instead of London.

Result:

- Faster loading
- Lower latency
- Reduced load on the London server

# Memory Trick

> [!TIP]
> Think of a **CDN** like a network of **local libraries**.
>
> - The **Origin Server** is the main publishing house.
> - The **Edge Location** is your nearest library.
> - If the book is available in the local library (**Cache Hit**), you get it immediately.
> - If it's not available (**Cache Miss**), the library requests it from the publisher, keeps a copy, and gives it to you. Future readers can then borrow it directly from the local library.
