# Introduction

One of the biggest advantages of cloud computing is **Elasticity**.

In traditional on-premises infrastructure, organizations must estimate how much computing capacity they will need before purchasing hardware. This process is difficult because application usage can change significantly over time.

If the organization purchases:

- **Too few resources** → Applications become slow or unavailable during high demand.
- **Too many resources** → Hardware remains idle, resulting in unnecessary costs.

Cloud computing eliminates this problem through **elasticity**, allowing resources to automatically adjust based on actual demand.

> [!IMPORTANT]
> **Elasticity enables cloud resources to automatically increase or decrease based on workload, ensuring applications have the right amount of capacity at the right time.**

---

# What is Elasticity?

## Definition

**Elasticity** is the ability of a cloud environment to **automatically add or remove computing resources** in response to changing application demand.

These resources may include:

- Virtual Servers
- Databases
- Storage
- Memory (RAM)
- CPU
- Networking resources

Elasticity ensures that applications continue to perform efficiently while avoiding unnecessary infrastructure costs.

---

# Why is Elasticity Important?

Application traffic is rarely constant.

For example:

- An online shopping website may receive millions of visitors during a festive sale.
- A streaming platform may experience a surge in viewers during a live sports event.
- A payroll application may only experience heavy usage at the end of each month.

Without elasticity, organizations would need to purchase enough hardware for **peak demand**, even though it would remain underutilized most of the time.

Elasticity solves this problem by automatically adjusting resources as demand changes.

# Traditional Infrastructure vs Cloud Elasticity

| Traditional On-Premises | Cloud with Elasticity |
|--------------------------|-----------------------|
| Capacity must be estimated in advance | Resources adjust automatically |
| Hardware must be purchased upfront | Resources are provisioned on demand |
| Risk of over-provisioning | Efficient resource utilization |
| Risk of under-provisioning | Automatically handles traffic spikes |
| Higher capital investment | Pay only for resources used |

---

# How Elasticity Works

Cloud providers continuously monitor application demand.

### When Demand Increases

The cloud platform automatically:

- Launches additional servers
- Allocates more CPU
- Increases memory
- Expands storage if required

This ensures users continue receiving fast responses.

---

### When Demand Decreases

The cloud platform automatically:

- Removes unnecessary servers
- Reduces allocated resources
- Stops idle instances

This minimizes infrastructure costs.

# Types of Scaling Used in Elasticity

Elasticity is achieved through two primary scaling methods.

1. Vertical Scaling (Scale Up)
2. Horizontal Scaling (Scale Out)

---

# 1. Vertical Scaling (Scale Up)

## Definition

**Scale Up** (also called **Vertical Scaling**) means increasing the capacity of an existing server.

Instead of adding new servers, the existing server is upgraded.

Resources that can be increased include:

- CPU
- RAM
- Storage
- Network bandwidth

---

## Example

A virtual machine initially has:

- 2 CPU cores
- 4 GB RAM

As application demand grows, it is upgraded to:

- 8 CPU cores
- 32 GB RAM

The application continues running on the same server with improved performance.

---

## Advantages

- Simple to implement
- No changes to application architecture
- Suitable for small and medium workloads

---

## Limitations

- Limited by maximum hardware capacity
- May require restarting the server
- Single point of failure

---

# 2. Horizontal Scaling (Scale Out)

## Definition

**Scale Out** (also called **Horizontal Scaling**) means increasing capacity by adding more servers or instances.

Instead of upgrading one server, additional servers share the workload.

A **Load Balancer** distributes incoming requests across all servers.

---

## Example

Initially:

- 2 web servers

During peak demand:

- 8 web servers

When traffic decreases:

- Back to 2 servers

---

## Advantages

- Virtually unlimited scalability
- Better fault tolerance
- High availability
- Suitable for cloud-native applications

---

## Limitations

- More complex architecture
- Requires load balancing
- Applications must support distributed processing

---

# Scale Up vs Scale Out

| Feature | Scale Up (Vertical Scaling) | Scale Out (Horizontal Scaling) |
|----------|-----------------------------|--------------------------------|
| Method | Upgrade an existing server | Add additional servers |
| Resources | CPU, RAM, Storage | Number of Servers |
| Complexity | Lower | Higher |
| Scalability | Limited by hardware | Virtually unlimited |
| Fault Tolerance | Lower | Higher |
| Best For | Smaller applications | Large-scale distributed applications |

---

# Elasticity and Auto Scaling

Elasticity is often implemented using **Auto Scaling**.

An Auto Scaling service continuously monitors application metrics such as:

- CPU utilization
- Memory usage
- Number of requests
- Network traffic

When thresholds are reached, the cloud platform automatically scales resources up or down.

This process requires little or no manual intervention.

# Elasticity vs Scalability

Although closely related, elasticity and scalability are not identical.

| Scalability | Elasticity |
|--------------|------------|
| Ability to increase system capacity | Ability to automatically adjust capacity based on demand |
| Focuses on growth | Focuses on dynamic adjustment |
| May require manual changes | Often automatic |
| Supports future expansion | Continuously responds to workload changes |

> [!NOTE]
> **Scalability** is the capability to grow.
>
> **Elasticity** is the ability to automatically grow **and shrink** based on demand.
