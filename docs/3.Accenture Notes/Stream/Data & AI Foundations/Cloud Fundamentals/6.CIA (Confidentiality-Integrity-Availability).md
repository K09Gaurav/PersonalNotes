# Introduction

The **CIA Triad** is one of the most fundamental concepts in **Cybersecurity** and **Cloud Security**. It serves as the foundation for designing secure systems, applications, and cloud infrastructures.

The acronym **CIA** stands for:

- **C** – Confidentiality
- **I** – Integrity
- **A** – Availability

Every cloud security mechanism is designed to support one or more of these three principles.

> [!IMPORTANT]
> The goal of the CIA Triad is to ensure that **only authorized users can access data (Confidentiality), the data remains accurate and trustworthy (Integrity), and the systems remain available whenever needed (Availability).**

# 1. Confidentiality

## Definition

**Confidentiality** is the principle of ensuring that **information is accessible only to authorized individuals**.

Its primary objective is to prevent unauthorized users from viewing or accessing sensitive information.

> [!IMPORTANT]
> Confidentiality answers the question:
>
> **"Who is allowed to access this information?"**

---

## How Confidentiality is Achieved

Organizations implement confidentiality through:

- User authentication
- Authorization
- Identity and Access Management (IAM)
- Role-Based Access Control (RBAC)
- Encryption
- Multi-Factor Authentication (MFA)
- Least Privilege Principle

---

## Cloud Examples

### Billing Information

Only users with the **Billing Administrator** role can view billing details.

---

### Personally Identifiable Information (PII)

Only authorized employees are allowed to access customer information such as:

- Social Security Numbers
- Passport Numbers
- Bank Account Details

---

### Development Resources

Developers are granted access only to the source code repositories or cloud resources required for their projects.

They are not given access to unrelated systems.

---

## Real-World Example

Consider a hospital management system.

- Doctors can access patient medical records.
- Receptionists can schedule appointments.
- Patients can access only **their own** records.

This separation of access ensures confidentiality.

---

## Best Practices

- Grant access only when necessary.
- Use Role-Based Access Control (RBAC).
- Encrypt sensitive information.
- Enable Multi-Factor Authentication (MFA).
- Regularly review user permissions.

---

# 2. Integrity

## Definition

**Integrity** ensures that **data and systems remain accurate, complete, and unaltered** unless modified by an authorized user.

Integrity guarantees that information can be **trusted**.

> [!IMPORTANT]
> Integrity answers the question:
>
> **"Can I trust this data?"**

---

## What Integrity Protects

Integrity applies to:

- Data
- Files
- Databases
- Applications
- Systems
- User identities
- Software
- Hardware
- Logs

---

## Why Integrity Matters

If unauthorized users can modify information:

- Financial records may become inaccurate.
- Medical records may be altered.
- Software may become compromised.
- Audit logs may lose credibility.

Maintaining integrity ensures that data remains authentic and reliable.

---

## How Integrity is Achieved

Organizations maintain integrity using:

- Audit logging
- Checksums
- Digital signatures
- Version control
- Access controls
- Data validation
- Backups

---

## Cloud Examples

### Logging

Every API request and administrative action is recorded.

Logs provide an audit trail that helps determine:

- Who performed an action
- What was changed
- When the change occurred

---

### Unique User Accounts

Each employee has a unique username instead of sharing a generic account such as **Administrator**.

This ensures accountability.

---

### Restricted Log Editing

Only a small number of authorized administrators can modify audit logs.

This follows the **Principle of Least Privilege** and helps preserve log integrity.

---

## Real-World Example

Imagine an online banking system.

If a customer's account balance changes from ₹10,000 to ₹100,000 without authorization, integrity has been violated.

Security mechanisms ensure that only authorized transactions can modify account balances.

---

## Best Practices

- Enable audit logging.
- Use digital signatures.
- Restrict administrative privileges.
- Implement version control.
- Verify data integrity using hashes or checksums.

---

# 3. Availability

## Definition

**Availability** ensures that **authorized users can access systems, services, and data whenever they are needed.**

A secure system is not useful if legitimate users cannot access it.

> [!IMPORTANT]
> Availability answers the question:
>
> **"Can authorized users access the system when required?"**

---

## Why Availability Matters

Downtime can lead to:

- Financial losses
- Reduced productivity
- Customer dissatisfaction
- Reputational damage

Cloud providers design their infrastructure to maximize uptime and minimize service interruptions.

---

## How Availability is Achieved

Cloud environments improve availability through:

- Multiple Regions
- Availability Zones (AZs)
- Virtual Private Clouds (VPCs)
- Internet Gateways
- Route Tables
- Load Balancers
- Auto Scaling
- Backup and Disaster Recovery

---

## Cloud Examples

### Public Website

A website such as **www.google.com** remains accessible 24 hours a day, 7 days a week.

---

### Remote Access

Employees working remotely securely access company resources through a **Virtual Private Network (VPN)**.

---

### Business Services

Authorized employees can always access:

- Email
- Cloud applications
- Databases
- Servers
- File storage

---

## Real-World Example

An e-commerce website during a holiday sale receives millions of visitors.

Cloud Auto Scaling automatically launches additional servers to keep the website available.

Customers continue shopping without interruptions.

---

## Best Practices

- Deploy applications across multiple Availability Zones.
- Enable Auto Scaling.
- Configure Load Balancers.
- Perform regular backups.
- Implement Disaster Recovery plans.
- Monitor infrastructure continuously.

| Description | CIA Principle |

| The data or information system can be trusted. | **Integrity** |
| The data or information system can be accessed only by authorized people. | **Confidentiality** |
| The data or information system is available when required. | **Availability** |

---

## Question 2

### Cloud infrastructure would have Integrity if...

**Answer:**

The infrastructure and its data remain accurate, authentic, and unmodified except by authorized users.

Examples include:

- Audit logging enabled
- Unique user accounts
- Restricted administrative access
- Verified system changes

---

## Question 3

### Availability is achieved when...

**Answer:**

Authorized users can reliably access systems, applications, and data whenever required.

Examples include:

- High Availability (HA)
- Multiple Regions
- Availability Zones
- Auto Scaling
- Disaster Recovery

>
> - **Confidentiality** → Only authorized people receive the vault key.

> - **Availability** → The vault is open whenever authorized customers need access.

# Interview One-Liners

**CIA Triad**
> The three core principles of information security: Confidentiality, Integrity, and Availability.

**Confidentiality**
> Ensures that only authorized users can access sensitive information.

**Integrity**
> Ensures that data remains accurate, authentic, and unaltered except by authorized users.

**Availability**
> Ensures that authorized users can access systems, applications, and data whenever needed.

**Personally Identifiable Information (PII)**
> Sensitive information that can identify an individual, such as a passport number, Social Security Number, or bank account details.

**Least Privilege Principle**
> A security principle where users are granted only the minimum permissions necessary to perform their tasks.
