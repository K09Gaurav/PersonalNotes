# Introduction

Networking is one of the **core pillars of cloud computing**. Every cloud service—whether it's a website, mobile application, virtual machine, database, or storage service—depends on networking to communicate with users and other cloud resources.

Without networking, cloud computing would not exist. It enables devices across the world to exchange information reliably, securely, and quickly.

> [!IMPORTANT]
> **Networking is the foundation of cloud infrastructure.**
>
> Every cloud service ultimately relies on a network to send and receive data.

---

# What is Networking?

## Definition

A **computer network** is a collection of interconnected devices that communicate with each other to exchange data and resources.

These devices may include:

- Computers
- Smartphones
- Servers
- Databases
- Printers
- IoT Devices
- Cloud Services

The **Internet** is the world's largest computer network.

---

# Why is Networking Important?

Networking allows us to perform everyday activities such as:

- Browsing websites
- Sending emails
- Streaming videos
- Video conferencing
- Online banking
- Cloud storage access
- Mobile applications
- Gaming
- Social media

Without networking:

- Websites would not load.
- Emails could not be sent.
- Cloud services would not function.
- Mobile apps would be unusable.

---

# Networking in Cloud Computing

Cloud networking refers to the technologies and services that enable communication between cloud resources, applications, and users over the Internet or private networks.

Cloud networking ensures that applications remain:

- Connected
- Secure
- Highly Available
- Scalable
- Accessible worldwide

---

# Components of Cloud Networking

Cloud networking consists of several important areas:

1. Network Architecture
2. Network Connectivity
3. Application Delivery
4. Global Performance
5. Content Delivery

---

# 1. Network Architecture

## Definition

**Network Architecture** is the overall design and structure of a computer network.

It defines:

- How devices connect
- How data flows
- Network topology
- Security boundaries
- Communication protocols

A well-designed architecture provides:

- High availability
- Reliability
- Security
- Scalability

### Examples

- Virtual Private Cloud (VPC)
- Subnets
- Route Tables
- Firewalls
- Internet Gateways

---

# 2. Network Connectivity

## Definition

**Network Connectivity** refers to the ability of devices, servers, applications, and users to communicate over a network.

Cloud providers offer reliable and cost-effective networking services that connect users to cloud applications anywhere in the world.

### Examples

- Internet connectivity
- VPN connections
- Private networking
- Dedicated cloud connections
- DNS services

---

# 3. Application Delivery

## Definition

Application delivery focuses on ensuring that applications reach users quickly, reliably, and securely.

Cloud providers improve application delivery using:

- Load Balancers
- Content Delivery Networks (CDNs)
- Auto Scaling
- Global routing

The goal is to provide fast response times regardless of user location.

---

# 4. Global Performance

Cloud providers operate data centers worldwide.

Applications can be deployed in multiple geographic regions so users connect to the nearest available resources.

Benefits include:

- Lower latency
- Faster response time
- Improved reliability
- Better user experience

---

# 5. Content Delivery

Content delivery involves efficiently distributing website content and application resources to users.

This is commonly achieved through a **Content Delivery Network (CDN)**.

Examples of content delivered through a CDN include:

- Images
- Videos
- CSS files
- JavaScript
- HTML pages

By serving content from locations closer to users, CDNs reduce latency and improve website performance.

# IP Address (Internet Protocol Address)

## Definition

Every device connected to a network is assigned an **Internet Protocol (IP) Address**.

An IP address uniquely identifies a device so that data can be sent to the correct destination.

Think of an IP address as a **home address** for a computer on the Internet.

Without an IP address, devices would not know where to send or receive information.

---

## Example

Google's servers have IP addresses.

Instead of typing:

```text
142.250.xxx.xxx
```

users simply type:

```text
www.google.com
```

The networking system automatically translates the domain name into the corresponding IP address.

---

# Why Don't We Memorize IP Addresses?

IP addresses consist of long numerical values that are difficult for humans to remember.

For example:

```text
142.250.193.78
```

is much harder to remember than:

```text
www.google.com
```

To solve this problem, the Internet uses the **Domain Name System (DNS).**

---

# Domain Name

## Definition

A **Domain Name** is a human-readable name assigned to an Internet resource.

Examples:

- google.com
- amazon.com
- microsoft.com
- openai.com

Domain names make websites easy to remember.

---

# Domain Name System (DNS)

## Definition

The **Domain Name System (DNS)** is often called the **"Phone Book of the Internet."**

DNS translates human-friendly domain names into machine-readable IP addresses.

Instead of remembering numeric IP addresses, users simply type a domain name.

DNS performs the translation automatically.

> [!IMPORTANT]
> **DNS converts domain names into IP addresses.**

---

# How DNS Works

Suppose a user enters:

```text
www.google.com
```

into a web browser.

The following steps occur behind the scenes.

---

## Step 1

The user enters:

```text
www.google.com
```

↓

---

## Step 2

The browser sends a request to a **DNS Resolver**.

↓

---

## Step 3

The DNS Resolver contacts the appropriate **DNS Server (Authoritative DNS Server)** to determine the IP address associated with the domain.

↓

---

## Step 4

The DNS Server returns Google's IP address.

↓

---

## Step 5

The browser connects to Google's server using the IP address.

↓

---

## Step 6

The Google website loads in the browser.

# What is a DNS Resolver?

A **DNS Resolver** is a service that receives DNS requests from users and finds the corresponding IP address.

Its responsibilities include:

- Receiving DNS queries
- Contacting DNS servers
- Returning the correct IP address
- Caching previous DNS responses to improve speed

---

# What is a Domain Authority?

When someone purchases a domain name, it is registered through a **Domain Registrar** (sometimes referred to in training material as a domain authority).

Examples include:

- GoDaddy
- Namecheap
- Google Domains (legacy)
- Cloudflare Registrar

The registrar records ownership of the domain and stores information about the authoritative DNS servers responsible for that domain.

> [!NOTE]
> Technically, the DNS lookup process uses an **Authoritative DNS Server** to provide the final IP address, while a **Domain Registrar** manages domain registration. Some introductory materials simplify these concepts.

---

# Real-World Example

Suppose you type:

```text
www.amazon.com
```

Your browser does **not** immediately know where Amazon's servers are located.

Instead:

1. The browser asks a DNS Resolver.
2. The resolver looks up Amazon's IP address.
3. The IP address is returned.
4. Your browser connects to Amazon's servers.
5. The website loads.

This entire process usually completes in just a few milliseconds.

Without DNS:

- Users would need to memorize IP addresses.
- Websites would be much harder to access.
- Internet navigation would be inconvenient.

DNS makes the Internet user-friendly by allowing people to use meaningful names instead of numbers.

# Real-Life Analogy

Imagine you want to visit a friend.

- **Friend's Name** → Domain Name (`www.google.com`)
- **Friend's Home Address** → IP Address
- **Phone Directory** → DNS
- **You** → Browser

You remember your friend's name, not their exact address.

The phone directory (DNS) tells you where they live so you can reach them.
