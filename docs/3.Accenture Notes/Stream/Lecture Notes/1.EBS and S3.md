What is EBS?

Amazon Elastic Block Store (Amazon EBS) is a service that provides persistent block-level storage for Amazon Elastic Compute Cloud (Amazon EC2) instances. 
 Simply speaking, this AWS service allocates reliable hard drives (that is, volumes) to cloud-based servers

EBS volume allows you to create a storage volume and attach it to EC2 instances. Once attached you can create a file system on top 
 of these volumes, run a database, OS or any other web application.

Elastic EBS Volumes is a feature that allows you to easily add additional volumes your EC2 instance to meet the business requirement.

Elastic Volumes allows you to dynamically increase capacity, tune performance with no downtime or performance impact.

EBS volumes are placed in a specific AZ where they automatically replicated to protect you from failure of single component.

EC2 instance loses its it root volume when it terminated

In general, EBS is DISK in cloud

You can also detach from instance and attach it to another instance

You can attach multiple EBS volumes to single instance

You will be billed for usage in GB's

What are the different EBS volumes types?

Amazon EBS provides different types of volume that differ in performance characteristics and price.

1) General purpose SSD(GP2, GP3)

2) Provisioned IOPS SSD (IO1, IO2) 

3) Throughput Optimized HDD (st1)

4) Cold HDD (SC1)

5) Magnetic Volume (previous generation)

6) General purpose SSD(GP2)

- It is used for system boot volume

- volume size (storage capacity) - 1GB to 16TB

- Max IOPS per volume - 16KB

- It is used for installing VM and databases

- It has low latency

-Cost:
 Gp2 volumes are fairly cheap, especially for the balanced performance they provide. They are priced at $0.1 per GB per month of provisioned storage.

NOTE:

1TB=1024GB
 16TB = 16384 GB

2) Provisioned IOPS SSD (IO1) 

- Best suited for Critical business application that require highest performance

- It can handle large database workloads both SQL and NOSQL databases

- volume size - 4GB to 64TB

- Max IOPS per volume is 256KB

- its cost is high
 usecase:
 we are running a PostgreSQL database on an EC2 instance that handles thousands of transactions per second, and you need consistent high IOPS and throughput.

Cost:
 This comes with a price—$0.125 per GB per month of provisioned storage and $0.065 per provisioned IOPS per month. This can amount to a costly solution in some cases, so be careful when provisioning these volumes.

3) Throughput Optimized HDD (st1)

- Frequently accessed and low cost hard drive volume

- Low-cost HDD volume designed for throughput-intensive workloads

- Streaming workloads require consistent, fast throughput at a low price

- It is suitable for Big data, Data ware housing and log processing etc.

- Cannot be boot volume (it’s too slow for that purpose)

- volume size - 125GB to 16TB

- Max IOPS per volume - 500KB
 (data warehouse, log processing server, or big data workload that reads/writes large files but doesn’t need low-latency random IOPS.)(Doesn’t need fast random reads/writes, Requires high throughput (MB/s), not IOPS)

-Cost:
 St1 volumes also come with a lower price tag: $0.045 per GB per month of provisioned storage.

4) Cold HDD (SC1)

-Throughput-oriented storage for data that is less frequently or infrequently accessed data

-Lowest cost HDD volume designed for infrequently accessed data

-Scenarios where the lowest storage cost is important

- Cannot be boot volume

- volume size - 125GB to 16TB,

- Max IOPS per volume - 250KB

Senario:
 Let’s say you have an application that archives logs from production servers once a month.
 You don’t access the data often — just store it long-term and occasionally retrieve it.

Cost:
 Sc1 volumes are the cheapest option available, costing only $0.025 per GB per month of provisioned storage.

5) Magnetic Volume(previous generation)

-Workloads where data is infrequently accessed

-volume size 1GB - 1TB

-Max IOPS per volume 40-200KB

Suppose we are running a very lightweight, legacy application that doesn't require much disk performance — maybe a simple internal tool or test environment where speed doesn't matter, and you're just keeping costs very low.

Cost:

Storage classes:

S3 lets you store data in a range of "storage classes". These classes are based on the frequency and immediacy you require in accessing files.

S3 Standard-frequent Access
 S3 Standard-Infrequent Access
 S3 Intelligent-Tiering
 S3 One Zone-Infrequent Access
 S3 Glacier 
 S3 Glacier deep archive
 S3 Standard Reduced Redundancy storage.

Let’s have a look at the different storage classes using the example of a school:

1)Amazon S3 Standard for frequent data access:

-It is the default storage class
 -It is used to store highly available and fast retrieval of data.
 -when data stored, it will replicate in more than 3 AZ
 -Suitable for a use case where the latency should below.
 -Its costly

 -Example: data of students’ attendance, which should be retrieved quickly.

2)Amazon S3 Standard for infrequent data access:

-Can be used for data like which is accessed less frequently and if needed that require rapid access 
 -Great for long term storage and Backups 
 -when data stored, it will replicate in more than 3 AZ
 -Less costly compared to standard.

-Example: Students’ academic records will not be needed daily, but if they have any requirement, their details should be retrieved quickly.

3)One Zone-iA Storage Class:

-It can be used where the data is infrequently accessed and stored in a single AZ. 
 -Great for long-lived, infrequently accessed, non-critical data
 -Cost 20% less than regular S3-Infrequent Access

-Example: Employees Performance is not used daily and stored in a single availability region

4)Amazon Glacier:

-It can be used where the data has to be archived, and high performance is not required.
 -Achieved data with retrieval time ranging from minutes to hours
 -Its very cheap storage
 -it is Optimized for data that is very infrequently accessed

 Example: Ex-student’s old record (like admission fee) will not be needed daily, and even if it is necessary, low latency is not required.

5) Amazon Glacier deep achieve:

- Long term archived for rarely accessed data

- Achieved data with retrieval time in hours

Example: A company needs to keep financial records, tax documents, and audit files for 7–10 years (for legal compliance), but no one accesses them regularly.

6)Amazon S3 Standard Reduced Redundancy storage:

 -Suitable for a use case where the data is non-critical and reproduced quickly.

 -Example: Books in the library are non-critical data and can be replaced if lost.

7)S3 Intelligent-Tiering:

-Designed to optimize the cost by automatically moving the data to the most cost effective access tier without
 performance impact and operational overhead

-It is the first cloud storage that automatically reduces your storage costs on a granular object level by 
 automatically moving data to the most cost-effective access tier based on access frequency, without performance impact, 
 retrieval fees, or operational overhead.

Difference between Block storage and S3 storage:

Block storage:

-It stores the data in the form of blocks

-If we do any changes in the file only block of that file will get update not the entire file (or all the blocks)

-It is best suited for server disks

-It is high performance in terms of read and write operations

-It can be assessed only through EC2 instance

-Cost is high

S3 storage:

-It stores the data in the form of objects in the bucket

-if we do changes in file, it will store in s3 as new version of the file

-Average performance with more read and less write operation

-Suitable for write once and read many times

-It cannot act as a disk so not suitable for storing OS and Database

-Directly we can access the data.(No EC2 instance is required to access)

-cost is low

S3 Lifecycle configuration:

-S3 Lifecycle configuration for automatic migration of objects to other S3 Storage Classes.

-It will define the lifecycle rules to define actions that you want Amazon S3 to take during an object's lifetime

For example, transition objects to another storage class, archive them, or delete them after a specified period of time etc.

Access control lists (ACLs):
 -You can use ACLs to grant read and write permissions to authorized users for individual buckets and objects.

-By default, when another AWS account uploads an object to your S3 bucket, that account (the object writer) owns the object, 
 has access to it, and can grant other users access to it through ACLs. You can use Object Ownership to change this 
 default behavior so that ACLs are disabled and you, as the bucket owner, automatically own every object in your bucket
